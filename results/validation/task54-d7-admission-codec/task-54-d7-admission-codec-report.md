## Limits and authority/owner semantics

Admission file/canonical limits are exactly **70,492,488 / 36,294,820**; Start exactly **2,097,152 / 2,097,152**. Admission exempts only `contract.canonical_bytes` (C=2,613,526 decoded bytes) and `selected_input.seed_receipt.canonical_bytes` (R=31,584,142); each is independently capped. Start has no exemption. Every other raw byte, quotes, key, separator, whitespace and escape is charged to A=2,097,152. Escaped large hex is refused even when decoded contents would fit. File limit, lexical path/token/depth checks and raw outer accounting precede typed serde/body allocations; actual blob allocation is preceded by even-length/lowercase/cap validation. No boundary-size file/blob is constructed by the new tests.

Existing depth16, decoded key64, ordinary4096, raw-OS hex8192, compiler16384, ID/version128, exact five policy documents, manifest512, features64, argv256, environment transport32/known unique seven-key vocabulary and inherited source/path/recheck checks remain. Actual exact current source/context/approved thread policy is still a future live reader obligation; the parsed CaseProvenance grammar does not create an approved context. No new numerical science/security/resource policy is introduced.

`parse_admission` and `parse_start` return private inert DTOs only. Standalone Start parse establishes bounded syntax/internal integrity, never fully verified start. Production rejects the private test schema regardless of marker and rejects synthetic=true regardless of rehash. Separate cfg(test) SyntheticAdmission/SyntheticStart wrappers follow the existing SyntheticTargetLock pattern; no production allow_synthetic API/feature exists.

- `check_target_claims(admission, parsed_lock, exact_reference_bytes, parsed_reference)` requires the reference already parsed by the existing strict production reference parser (test-only helper uses inherited strict Fields/records and digest verification under its explicit private domain). It checks exact supplied reference file bytes against parsed file hash, payload link, lock/reference/admission duplicated links, campaign/profile/lock ID/policy/contract, available reference projections and lock<=admission wall time. An arbitrary reference payload text is never decoded as a trusted link. Actual writer-capsule approval is unavailable from outer source claims and remains an explicit live-reader prerequisite.
- `check_start_claims(start, admission)` checks every duplicated identity/input/policy/lock/reference/attempt/admission link and admission<=start wall time. It does not inspect disk or current context and does not replace `check_target_claims`/live verification.
- `check_predecessor_claims(current, prior, explicit_optional_prior_start)` requires Retry, distinct attempts, same campaign/profile/case/seed and exact contract/selected input; checks prior admission links/time and present prior start links/full start-admission claims/time. Presence versus absence is explicit and mismatches reject. Initial null eligibility, process liveness, failure/finished status, current on-disk absence or concurrency are never inferred.

All parsed gate revisions/hashes are **claims**, not passed evidence or leases. Case/execution tags—including external/native roles—do not enable adapters or construct HE contexts. No Parsed/DTO -> VerifiedReference/VerifiedTarget/CheckedCase/admission/start capability conversion was added. DTOs do not implement Deserialize/Clone into live authority.
