## 1. Decision and reason

Connect one genuine CPU Main/BatchedDiagonal path through the existing retained runtime, canonical preparation and frozen descriptors, then the already specified full admission/start protocol, then the exact returned-driver handoff. Do not build a generic gate plugin system, pass-bit manifest or arbitrary callback executor. Keep all registered rows visible while unsupported adapters remain explicit missing-code states. Full encrypted blocks remain held even when their disconnected implementation passes.

The immediate implementable units are (a) request/owner plumbing and actual outer ExecutionBinding production, (b) the missing durable admission/start codec and held-handle protocol, and (c) sealed concrete gate constructors and evidence readers. Their positive scientific availability must follow actual evidence; none is supplied by this document. A full ordinary single-stage CPU case is the first coherent production branch. Both I and NI must remain explicit; success of I never establishes NI. Quick reuses preparation/ownership but is an operational branch outside full target admission (§9).

Reasons: actual source already supplies the difficult canonical input, runtime ownership, plan and preparation machinery. The missing work is joining those concrete owners to durable authority and preserving them through crypto teardown. A second implementation manifest, alternate source provenance, new parameter preset, synthetic StartedHeCase or Ready enum would add ambiguity without supplying evidence.

Rejected alternatives:

- Treat P1/P3/descriptors as all passing gates: they deliberately leave range, precision, actual key/security binding and resource fit unproved.
- Demand successful accuracy/performance of the new full run before admitting that same run: circular; preserves neither the requested experiment nor honest failures.
- Run legacy binaries from the shell and attach retrospective admission: violates lock-before-start and current-role/input/build ownership.
- Implement a general scheduler/resource service: unnecessary for a first serial campaign. Use a concrete held local execution claim plus current OS observations; do not call a cooperative claim a physical memory reservation.
- Reuse full target receipts for Quick: expressly forbidden by target design §5 and changes the meaning of prospective results.

## 3. Correctness prerequisites versus outcomes: required narrow ruling

The primary plan `../plans/2026-11-04-he-training-research-plan.md` §日程と品質 states: “正当性のゲート(KAT、セキュリティ確認、非対話学習が動くこと)は緩めない”; performance goals may be missed and honestly reported. §4.3.2 fixes RQ1 same-N/security/model, accuracy ±0.5 pt, KS reduction at least30%, and same-CPU wall-clock conditions. Those are comparison outcomes, not values one can prove for an unexecuted new study row. `docs/experiment-matrix.md` §target states FP32−0.005 is a time-to-target convention, explicitly not an accuracy acceptance gate. Bootstrap≥16bits, ≤220ms and HEonGPU comparisons keep their existing meanings; no new thresholds are proposed.

The eight P3 `UnprovedGate` names are a list of what metadata did not establish, not an implemented eight-bit preflight policy. Existing D7 text says applicable policies must be satisfied without specifying, for every item, whether the evidence is prerequisite, construction obligation or measured result. Requiring actual newly sampled keys, encrypted values or final accuracy before keys exist is impossible. **Ratify this precise staging before wiring a positive constructor:**

1. Before admission: canonical source completeness, valid route/layout/levels/scale metadata, existing applicable KAT/implementation-correctness evidence, security evidence matching the exact declarations and reviewed sampler/key-generation branch, physical resource feasibility, actual authorized scope, and full target lock must hold. Existing failed or missing correctness evidence stays a failed/missing prerequisite; small mini tests do not become secure-N proof.
2. After durable start, before any affected encrypted operation: check actual factory parameter/key ownership and declared secret contract through the reviewed factory; enforce encoding/range/finite-value preconditions that are mathematically required by the operation. Failed setup consumes authority and leaves incomplete start. This is an obligation carried by the implementation/layout capabilities, never a pre-start claim that the random keys already exist.
3. During/after the run: record real approximation/precision, NI success, accuracy, counters, latency and time-to-target. Failed correctness invalidates that scientific row; unmet performance targets are measured failures/misses, never repaired. Diagnostic work is explicitly counted and separated from training timing. Existing source-defined runtime invariant failures remain fatal/poisoning.

This interpretation does not waive KAT/security/NI correctness. It allows the authorized experiment to measure unknown row outcomes while enforcing known prerequisites. If root determines the existing NI correctness gate specifically requires secure-N evidence that is presently absent for this exact route, the NI constructor returns missing-evidence and the existing bounded validation owner closes that gap; do not launch a new prerequisite campaign by inference. No numerical tolerance is borrowed from P5's mini-fixture caps or invented from the target.
