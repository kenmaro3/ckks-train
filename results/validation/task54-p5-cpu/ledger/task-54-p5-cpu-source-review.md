## QUALITY notes and limitations

1. **Minor — public snapshot preconditions are implicit.** `study_blocks.rs:1094–1124` uses `completed.saturating_sub(1)` for row metadata but copies the current I recorder/current model. Before a first success it produces an incomplete handoff snapshot; after a later poisoned attempt it can pair current failed-prefix I outputs with the preceding successful update's valid-row metadata. NI outputs may instead be empty, or retained from a prior success if failure precedes the wrapper. The frozen test calls this endpoint only immediately after success, so its matrix is unaffected. Document that success-only precondition, or make unsupported-state export reject explicitly before this API is used more broadly. Do not describe such exports as a coherent failed-attempt model/handoff endpoint.

2. **Minor — negative-test temporary copies need more precise prose.** `p5_tests.rs:459–478` adds a duplicate target and temporary original/replacement ciphertext payloads while checking extra-target/xlevel/yscale rejection. The emitted RawSnapshot retention receipt is taken before those mutations, and these transient allocations have no separately emitted role/byte entry. The receipt honestly lists caller diagnostic copies as unobserved (`study_blocks.rs:1385`) and makes no peak/RSS claim; the 46+2 capture accounting is correct. However, the author report's blanket statement that every clone is a distinct accounted payload role is broader than the implemented observation. Name these temporary negative-mutation copies as excluded diagnostic workspace, or add scoped accounting if complete diagnostic payload coverage is later claimed. This does not require another capture, key, encryption or runtime attempt.
