# Task54 P4 — bounded synthetic CPU bridge validation

This archive records a small Mac CPU contract test of the actual single-stage encrypted training bridge. It is **non-scientific validation**, not a dataset accuracy/performance measurement or canonical production admission. Client-owned secrets and private encrypted packets feed existing interactive/non-interactive trainers; the implementation checks bound configuration, state, counters, progress and failure behavior. No optimizer recurrence is copied.

The independently reviewed final source passed compile-only validation, strict Clippy and formatting. The actual selected ignored contract test then passed: **32 successful updates, two intentional midwork failures, 20 sessions and 71 real bootstrap invocations**. Its all-entry W/b comparisons cover 12 interactive and 20 non-interactive updates. Maximum absolute errors were `7.64926433305390674e-9` and `1.89993002996935445e-8`, respectively, against frozen caps `1e-5` and `4e-4`. The test also completed 268 exact unchanged-state comparisons for rejected packets/replays/poisoned retries. This evidence applies only to the reviewed synthetic cases.

The first actual invocation failed before keys/HE: a private synthetic fixture with current rate .04/reference .08 incorrectly called the canonical full-maximum rate policy. That failure is retained. The reviewed correction uses the existing field codec for that private fixture, preserving the canonical validator, rates, reference and tolerances. The second invocation is separately recorded; cumulative work includes the failed invocation. No automatic retry or hidden failed numerical run is represented as success.
