### I1 — Important/P2: owned target accepts a later store at the same address and loses the original guard association

**Locations:** `crates/ckks-train-bench/src/study_reference/target.rs:160`, `:174`, `:384`; `crates/ckks-train-bench/src/study_provenance/publication.rs:784`; `crates/ckks-train-bench/src/study_provenance/publication/retained.rs:88`.

`VerifiedTargetForSeed` intentionally owns its snapshot without borrowing the short-lived store. Its only original store identifier is `usize`, captured from `self` in read_target and compared with the current argument's address in check_attempt_history. Unlike ContextOwnerStamp, this store association has no never-reused identity or retained identity allocation. Rust permits replacing the value in the same store variable after read_target returns. The address comparison then succeeds for a different store instance.

Source-level reproducer (not executed):

1. Open original store S with context C; call S.read_target to obtain owned target T. T retains the original lock/reference Files and parent anchors but does not borrow S.
2. Open another store S2 for the same campaign/profile/context and assign S2 into S's existing variable/place. That place/address remains the same; the original store value is dropped. Even without filesystem changes, T now accepts a different store as its original owner.
3. A stronger case replaces `.profile-guard` between those opens while leaving target.lock.json, its parent and the reference intact. The replacement store records the new guard inode at publication.rs:741. Its `recheck` validates that new guard against itself. T has retained neither the original guard identity nor an owner token that distinguishes the old store.
4. T.check_attempt_history(&S, ...) passes the address check, the unchanged context instance/process checks, and recheck_read: the latter compares the retained Target role/name/parent and rechecks the **replacement store's** guard. Valid current/prior records can then pass C1. Original guard continuity was not established.

This is an ownership correctness failure, not unsafe pointer dereferencing or evidence that live HE is currently reachable. The private adapter is deliberately inert, but this source package explicitly promises the prerequisite SAME-store/guard association; accepting it now would carry the defect into later admission integration. The compile-only short-store example correctly shows FD custody survives drop, but cannot prove original-owner continuity. The equal-value Boxes test exercises context pointer comparison, not this store replacement case.

**Narrow remedy:** give each actual ProfileTargetStore a private retained allocation identity (for example, an Rc-owned private token, shared only with its snapshots and compared with Rc::ptr_eq), or a checked never-reused store instance number. Retaining the allocation in T prevents allocator/address ABA while allowing store drop and retained FD custody. Keep the required original address/context checks where the contract requires them. Also retain and compare the original guard association; do not replace it with whichever guard a reopened store observes. A held original guard source/identity can make that continuity explicit without keeping an execution flock held through HE. No public reconstruction, pass flag, serde/Clone live capability or generic permission object is needed.

Add a bounded pure test using the actual private identity comparator: same original owner accepts; distinct owner with equal metadata refuses; replacing an owner in the same address/place refuses; old identity remains alive after original store drop. Preserve both independent-lifetime compilation obligations. Add separately inventoried native guard-replacement/source-owner coverage before claiming native continuity. These additions are recommendations for a separately assigned source fix, not execution authority from this review. Root confirmed I1 is binding under original SAME-store/guard requirements; runtime remains unreleased pending fix/review.
