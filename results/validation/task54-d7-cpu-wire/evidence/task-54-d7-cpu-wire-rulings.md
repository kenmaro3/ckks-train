# CPU wire implementation rulings

## R-WIRE-1: standalone initial-sample framing

The adopted FIX2 contract names the full samples stream domain but leaves the single initial-sample domain/header and the order of its pending link implicit. Resolve before any production encoder/consumer is implemented as follows.

`initial-sample.bin` is one standalone document, using the existing encoding header, domain `hekit-study-resource-observed-initial-sample-v1`, synthetic=false. Its body is exactly the existing Sample record fields in the order listed in FIX2 (seq,started,finished,phase,processes,sum_kib,valid,status), then exactly one pending FileRef. No list wrapper, stream claim header or u32 frame-length prefix appears in this standalone body. Exact EOF is required and the whole document remains subject to A cap. Private fictional oracle domain is `hekit-test-resource-observed-initial-sample-v1` with synthetic=true; the production consumer rejects it. Sample fields are shared encoding, not a duplicate alternate algorithm. The pending link must match the actual resource pending in later bundle/owner checks; decoding cannot establish that authority.

Full sample streams retain `hekit-study-resource-observed-samples-v1`, existing header followed by claim FileRef then the specified incremental u32-length-framed Sample records. The two forms are not interchangeable and their parsers must reject the opposite domain/framing. Nothing in this ruling changes sequence/clock/process identity validation, scheduling, aggregate limits, durable ordering, or the pending->initial->claim acyclic links.

Reason: the standalone initial observation precedes the claim and cannot use the later stream's claim header. Separate exact domains remove interpretation by path or guessed payload shape. Alternative was reuse of the stream domain with a newly tagged header variant; this would add an avoidable branch and replay ambiguity. Cost if wrong is format incompatibility within this not-yet-published implementation; preserve the original proposal and update producer/consumer/independent vectors together before any native use. Original frozen provisional initial vector already uses this selected layout and must be retained, not relabeled as evidence derived from production code. Add explicit cross-domain/framing rejection coverage. This is a narrow clarification, not a new operational or scientific gate.

## R-WIRE-2: demand conservation, site syntax and result policy

Resolve the implementation's remaining three concrete interpretations before their encoders are written. No field/domain change is introduced.

1. SourceDemand requires checked u64 arithmetic: for each allocation compute count*element_bytes without overflow, sum all products without overflow, and require exact equality with the checked sum retained_payload_bytes+additional_payload_bytes. This is a representation consistency rule only. The format has no per-allocation residency tag, so it cannot independently prove which owners contribute to either subtotal. The genuine producer must derive both subtotals and allocation records from its actual retained/incremental owners and phase; do not infer that attribution from caller numbers, a successful sum, or names. Unknown overhead remains outside these payload fields, not a zero-sized entry or physical-fit claim.

2. A site Id is exactly one listed family, or that family followed by underscore and a canonical decimal u64 index. Decimal is `0` or a nonzero digit followed by digits, with checked u64 parse. No sign, leading zero, whitespace, extra suffix or unknown prefix. Match the complete family name before its optional suffix (e.g. decoded_f64 and decoded_f64_0); do not split at the first underscore. Existing sorted-unique site rule and512allocation cap remain. Actual source traversal chooses indices deterministically for distinct owners/phase and must not count one owner twice under bare/indexed aliases. The decoder cannot identify physical ownership. Do not add fake-owner authorization or an undocumented index-order/contiguity rule to wire parsing.

3. Scientific result.policy is exactly `d7-resource-observed-rss-v1` and must agree with the selected observed-resource evidence and new fixed policy tuple. Historical static resource policy is not accepted on this result path. This field is an identifier, not serialized arbitrary policy content.

Reason/alternatives: explicit conservation and closed canonical suffix syntax resolve otherwise ambiguous byte claims without changing the ratified fields. A new retained/incremental tag per allocation would be a format redesign and is unnecessary for the inert record; actual source attribution remains a live producer obligation. Permissive arbitrary suffixes or arbitrary result policy IDs would allow ambiguous source accounting or mixed-policy replay. Cost if wrong is a rejected representation or unproved attribution, requiring revision before native use; these pure checks do not discharge owner/sizing/native obligations. Preserve all preimplementation independent vectors and retain any genuine failed expectation instead of rewriting it to match production code.

## R-WIRE-3: first target coordinate and JSON writer order

`TargetOutcome.first_checkpoint` means the completed-update coordinate (`Endpoint.updates`) of the earliest scheduled endpoint whose exact held-out accuracy reaches the locked target. It is not a zero- or one-based array ordinal or an epoch number. On the registered Iris Full schedule the first possible coordinate is6, not0/1; the source plan remains authoritative for other schedules. `time_ns` is that same endpoint's cumulative inclusive server/update time. Unreached means first_checkpoint=None,time_ns=None and censor_ns from the last completed scheduled endpoint under the existing completion/failure rules. No checkpoint interpolation or best-checkpoint selection is introduced. Actual target threshold still comes from verified locked seed0 evidence.

Reason: the existing Reference endpoints expose completed_updates with cumulative update timing, and this coordinate remains meaningful without a consumer guessing an array base. Alternative was an explicit zero-based endpoint index; that would require an additional semantic conversion and invite confusion with logical boundaries. Cost if wrong is incompatible interpretation of prospective result values, so record the meaning now and test a case whose endpoint ordinal and completed-update coordinate differ. Original independent expectations and any genuine failed draft assertions must be preserved.

Counter JSON names are exactly existing Counter fields in declaration order: rotations,relins,ct_ct_tensor,ct_pt_mults,rescales,sse_switches,bootstraps. Times JSON names/order are setup,server,bootstrap,refresh,input_encryption,diagnostic,fp32,end_to_end,publish. Underscore spelling in JSON makes the prose's input-encryption/end-to-end fields unambiguous. The result writer emits objects in the contract's listed field order, including these Counter/times names; deterministic typed serialization or existing primitives suffice without dependency changes. The decoder accepts reordered object members while enforcing exact field names, uniqueness, types and canonical reconstruction. Canonical binary field order is always exact. Attempt/export whole-file JSON equality remains exact, so export is a byte copy of the same generated JSON rather than independently serialized equivalent JSON.

Reason/alternative: preserve the explicitly specified writer order and standards-compatible object parsing. Lexicographic map output would be semantically reconstructible but would not meet the stated writer-order convention; requiring member order on input would add an unnecessary restriction to strict JSON interpretation. This clarification changes no numbers, fields, limits, wire order or live authority.
