Use the step2 private retained owner after its independent acceptance, not a parallel reader. The proposed names here describe interfaces for the next source brief, not implemented types or approved public API.

## 5. Sequencing and the genuine dependency cycle

What can be decided before raw acquisition: current context/source approval identity; fixed registry/lock identities; actual selected RegisteredCase/profile/seed/backend/role; request and parameter recipe; complete expected file roles/paths/hashes/exactsizes; registered shapes/train/test/classes/graph/init/order/schedule rules; full logical row/update/checkpoint counts; expected format/header and serialization bounds. Bounded metadata parses must themselves be admitted under a reviewed bootstrap/preparation resource model. They are not free merely because each file is≤8MiB.

What cannot be honestly claimed yet: materialized numeric hashes, actual order/init/rate/data correctness, actual canonical input receipt, actual preparation descriptors/accounting, verified target/reference science and selected receipt, final execution/applicability identity, complete physical model validation/current capacity/claim. Metadata selecting a required file does not prove those later results.

The baseline cycle is concrete: `run_owned` needs materialized input to create actual plan/preparation/execution binding; the Resource wire's applicability binds that final execution/input, but obtaining those values already allocates raw/decoded/receipt/preparation memory. Calling final Resource validation after materialization cannot retroactively authorize it. Constructing provisional fake hashes or a fake final gate to break this cycle would violate the design.

Required source ordering under the accepted preacquisition rule:

1. Establish the real context/runtime and reviewed bounded control-plane acquisition phase. Runtime/thread-pool owners already created by dispatch are real pre-existing residency, not allocations retrospectively licensed by this check; any residency credit requires the same actual later capacity snapshot. The pre-raw boundary specifically must cover all further raw/decoded/preparation allocations. The producer's trusted model/validation selection must originate in current context/approved source, not from an untrusted Resource record or paths learned from raw data. Include actual bootstrap buffers/helper/runtime allocation in that model. If this initial model/capacity/claim channel is absent, stop there; an unbounded scan to discover it is not acceptable.
2. Acquire only fixed metadata, bind actual RegisteredCase and selected profile/seed, then complete the closed expected inventory and conservative source-specific preparation work inventory before raw acquisition. If a necessary metadata parse also needs additional capacity, check it before that parse; the concrete model must specify those boundaries. No new guessed metadata allowance is proposed here.
3. The SAME concrete resource producer verifies its reviewed physical model+validation applicability to the actual source/build/registered inputs/runtime/request and observes actual host MemAvailable, complete applicable cgroup leaf-to-root hierarchy, disk and cooperative claims. Its preallocation phase covers raw bytes, decoder/temporary/independent-reader overlaps and later required allocations, before issuing acquisition work. Unknown allocator terms or an incomplete22-component model means missing evidence. Existing limit semantics stay intact.
4. Acquire exact retained files, verify bytes/header/shape/hash and then decode/assemble from them. Model validation must justify the bounded path for malformed input too, including refusal before array construction where expected header shape mismatches. Recheck descriptor/origin identity after bounded reads. Preserve owner and raw bytes. Failure releases actual temporary ownership/claim through normal lifetime, never fabricates a gate/event.
5. Independently reconstruct required reference seed0 and selected target seed from those retained, context-bound inputs, with their real source inventories (including reference-seed selected files when distinct). Dataset/shared sources may be borrowed from the same immutable owner if identity truly matches; different seed init/order remains distinct. Do not elide independent numeric reconstruction or charge two separate raw allocations when one actually serves both. Recheck current source/origins throughout required boundaries.
6. Derive actual receipt, plan/preparation/execution facts; close the later Resource evidence applicability against them using the SAME producer, model, observation/claim ownership. Refresh observations/rechecks at required live boundaries; any mismatch/staleness refuses. A later snapshot can only justify residency credit for allocations actually charged in that same snapshot, with appropriate host/cgroup accounting; no retroactive approval or double subtraction.
7. Only after all five genuine owners/readers exist can guarded publication, durable admission, start and consuming begin transfer custody. Keep existing context+ProcessStamp, read-stamp/currentness, prepared accounting/plan and resource/user owners alive. Full C1 checks both current/prior against one verified target/reference/policy; Quick remains target-free and cannot promote into Full.
