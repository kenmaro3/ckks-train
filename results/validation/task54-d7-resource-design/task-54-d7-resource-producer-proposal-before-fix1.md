# Task54 D7 — phase-aware resource producer proposal

Status: **PROPOSED; not ratified, source authority, model approval or runtime release.** Fixed source BASE `71d3f0937741a4ff8d156b36540332ea82203d3c`; no concurrent step2 source inspected. The accepted dependency map `31504e7c` remains unchanged. This proposal selects a small CPU implementation boundary for the next genuine typed-materializer integration. It does not substitute for runnable paper tables, all21 profiles/full2680+20+7/quick268, GPU/external support, original holds or scientific/security evidence.

## Decision and required rulings

Use **one private resource owner**, created before context/registry/model metadata expansion, retaining a **single stable per-host serial execution flock** from initial capacity check through all owned-resource teardown. It evaluates source-specific compiled allocation rules, checks real Linux capacity, feeds the SAME retained canonical bytes into the existing typed materializer, and only later binds final actual execution applicability. No sixth gate, generic expression evaluator, scheduler, signing service, caller permit or new user approval layer.

Three refinements require independent design review before source/encoder changes:

1. **Resource exclusion versus publication flock.** Accepted live-gate proposal §5 requires a cooperative claim through crypto teardown; custody §5 says Quick executes with “no flock held.” Specify that publication/profile guards are released during HE, while this distinct host resource flock remains held. Without that explicit clarification, this selected mechanism cannot be implemented as conforming. Alternative: another kernel-held exclusion mechanism or multi-claim registry; both add lifecycle/race complexity without enabling requested science. Keeping the literal prohibition leaves resource claim implementation missing.
2. **Structural cgroup root.** V2 global root has no `memory.current`/`memory.max`. Do not synthesize a zero-current row or treat a namespace root as global root. Propose `Observation.cgroups` contains every applicable *accounting interface* from the process leaf through its ancestors; `host_raw` additionally proves traversal to the real structural root and records its kernel-defined lack of a local memory limit. Empty is permitted only with proved no applicable accounting interface, including the verified global-root case. This is a semantic clarification of the existing list/empty rule; byte grammar stays unchanged. Alternative: version the outer Resource schema to encode a structural-root variant, costing new goldens/codec work; or refuse such observations until that extension. Until this ruling is ratified, do not claim the proposed root handling satisfies the old literal empty rule.
3. **Closed retained source formats and observation namespace.** Define the small report formats below and store immutable claim/observation artifacts beneath the already trusted Observation root, outside attempt trees. Independent literal vectors must precede encoders. Existing Resource/Requested/Requirements/Observation/Claim/FileRef and Full/Quick formats/caps remain unchanged. These source records explain existing FileRefs; they are not new admission events. If their required inventory cannot fit existing caps, return missing evidence and seek a specific refinement; never truncate.

## 2. SAME owner, noncircular phase order

Implementation seam: a private `study_provenance::resource` owner with closed model, Linux-observer and serial-claim helpers; it reuses the accepted step2 retained reader and shared publisher. No exported general budget or provider trait. `ResourceOwner` is private, non-Clone/non-Send/non-Sync; only actual launcher/context origin and checked source readers can construct it. It owns the lock File/ancestors, ProcessStamp, current context association after context construction, model/validation bytes and origins, selected work envelope, observations and immutable claim. Proposed methods are internal sequencing points, not public permits:

1. **Fixed bootstrap probe → bootstrap envelope.** Before loading/expanding model/context/registry files, a minimal Linux observer uses fixed source-sized scratch and safe descriptor syscalls to check host/cgroup/disk capacity under the stable lock. Its own code, stack/scratch, path/line processing, errors and supported kernel/allocator profile need a separately reviewed *compiled bootstrap bound*. That bound is generated from reviewed source reasoning and native validation at build/release time and bound to the approved executable/source; it is not obtained from the large model file it is supposed to authorize. No numeric bound is supplied in this proposal. Until established, the positive bootstrap constructor remains unavailable. Pre-existing process/runtime/thread-pool memory is observed existing usage, never retrospectively authorized or credited from guesswork.
2. **Bounded metadata.** Bootstrap envelope covers complete retained model+validation+host-policy/context/registry/lock/config/source bytes, parser expansion, hashing/helper work and evidence storage needed to resolve ONE actual selected case. Read fixed model paths under existing caps, verify package applicability and actual host profile, then create actual context/RegisteredCase and complete the selected canonical inventory. Bootstrap capacity is not inferred from serialized byte counts; JSON trees/Vec growth/allocator/parser scratch and recursive verification metadata must be accounted. The validation package's raw logs can be hashed with bounded readers; they must not trigger arbitrary nested reports or unbounded decoding. No model file can authorize expanding itself before the compiled envelope check.
3. **Selected-case envelope, before materialization.** Evaluate preparation bounds using approved registry/locked metadata, requested consumption/lanes/eval/transpose, constant parameter recipe and model rules. Use actual input exactsizes and metadata dimensions/order counts; do not call `materialize`, `plan_diagonal`, `CkksParams::new` or the crypto constructors to discover their preallocation budgets. Use reviewed pure sizing projections over those constants. Bound any parameter metadata/geometry/plan construction before constructing it. At this stage reserve a conservative source-derived *envelope*, including nested reference seed0 and selected-seed reconstruction, then observe capacity and create immutable claim. No final execution hash exists yet.
4. **Acquire/decode/prepare.** Under the SAME owner, acquire the exact closed raw files and pass those immutable bytes through the mapped typed loader; preserve all preprocessing/hash/shape/order/init semantics. At each new allocation family check its modeled remaining demand and fresh observation. Actual constructed quantities may refine the envelope only downward when justified by the SAME rules; if actual shape/count/lifetime exceeds it, stop before the affected allocation, not after. Final materializer and independent reader allocations must stay inside the envelope including failure-path buffers.
5. **Finalize actual applicability.** Derive actual retained canonical input/receipt, plan/accounting, params, execution/runtime/security/layout/key descriptors. Compare all to the selection and sizing assumptions, then build existing Resource with actual Applicability/Requested/Requirements/Observation/Claim. No provisional hashes, fabricated gates or reconstructed owner. Final observation and claim refs are immutable snapshots; current rechecks never rewrite sealed sidecars. A model valid only for preparation cannot pass the all-phase final gate.
6. **Admission/start/begin/update/endpoint/teardown.** SAME resource owner survives all five-gate assembly, guarded sidecars, durable start, transfer to live frame, crypto setup and teardown. Refresh observations immediately at existing allocation/live boundaries and reject changed source/environment/claim origin. No publication/profile flock held during HE; distinct host resource lock remains, subject to ruling1. Error/drop destroys crypto, prepared/data/raw/evidence owners covered by the claim, then closes the claim lock last. Returning a plain outcome cannot transfer resource authority.

No self-referential owning struct: keep source/model/context/materialized owners as outer frame locals and borrow inward; transient JSON views never outlive their owned buffers. Preserve original plan Arc and PreparationAccounting. Reacquiring another lock or loading identical model bytes into another owner does not resurrect a consumed frame. If finalized execution differs from the selected envelope, restart only through a new ordinary explicitly authorized invocation, never grow the claimed budget silently.

## 4. Concrete Linux observer

Safe Rust/rustix calls only; reuse retained-root/ProcessStamp machinery after its accepted integration, without adding unsafe or altering shared publisher. No `free`, `df`, shell, arbitrary PID scans, cgroup writes, mount changes, sysctls or allocator reconfiguration. Native support and filesystem behavior need later tests.

- **Origins/topology:** capture actual `/proc` filesystem and own process directory, `/proc/self/cgroup`, `/proc/self/mountinfo`, `/proc/cgroups`, kernel boot identity and namespace identities; open cgroup mounts through trusted held ancestors matched to the actual mount table. An apparent `/` in a cgroup namespace is not proof of the host root. Host policy/launcher must establish actual initial host namespaces; hidden ancestors or unverifiable mount-root mappings refuse. Recheck boot/ProcessStamp, membership, mount mapping and root identities around each observation. Bound all raw reads by8MiB, paths by existing4096, source/list counts by existing limits; use checked conversion and EOF/growth detection rather than procfs st_size. Oversize/unknown/permission/I/O/parse/topology errors mean missing observation, no retry-until-pass loop.
- **Host:** read exact `/proc/meminfo`; require one well-formed `MemAvailable` in kB, checked×1024. Never substitute MemFree/swap or add cached memory again. Bracket the controller read with two meminfo reads and use the smaller observed MemAvailable; retain both. This is still a kernel availability estimate, not reserved RAM. [Linux meminfo manual](https://man7.org/linux/man-pages/man5/proc_meminfo.5.html)
- **V2:** determine the actual memory accounting domain, walk *every* ancestor to the verified global structural root. Read `memory.max` (`max` alone means unlimited) and `memory.current` for every applicable non-root accounting interface; keep the exact ordered paths/raw values, even unlimited ancestors. Check controller placement/domain metadata, never silently omit a parent because the leaf has a limit. Reread limits/topology after the pass; changes refuse. Counters may change, so no atomic-snapshot claim. Threaded/domain-invalid or unsupported placement stays unavailable until its concrete mapping is validated. Root-interface absence follows ruling2, not ENOENT-as-unlimited. [Kernel v2 interface](https://docs.kernel.org/admin-guide/cgroup-v2.html)

Normalize unlimited only from the exact supported kernel/page-size implementation, never “very large means unlimited.” V1 usage batching/kernel-accounting variations require a validated observer profile; absent that evidence, report unsupported v1 observation rather than relabel it v2 or use host capacity alone. V1 docs themselves warn about age, so kernel source-specific validation is mandatory. Hybrid topology must prove which hierarchy owns memory; no guessed union or dropped controller. [Kernel v1 documentation](https://docs.kernel.org/admin-guide/cgroup-v1/memory.html)

Exactly existing comparison, no extra headroom constant. Current readings can race noncooperative consumption or administrator limit changes after observation; every required allocation/update boundary rechecks. A successful comparison is prospective evidence under those checks, never immunity to OOM. Later allocation failure is failure, not retroactive resource skip.

No double counting of already consumed blocks as future need. Quotas/remote/overlay/tmpfs or unsupported filesystem accounting require validated quota/backing-memory evidence; `f_bavail` alone cannot prove an unobserved quota. [fstatvfs manual](https://man7.org/linux/man-pages/man3/statvfs.3.html)

Use one bounded topology-bracketed observation pass, with explicit begin/end clocks and raw hashes. Do not demand usage counters remain equal, manufacture a nonexistent atomic instant, or introduce an arbitrary observation TTL. Immediately use the result at the named boundary; any intervening allocation under this owner is charged, any context/claim/topology change refuses. Namespace and interface origin checks are distinct from comparing immutable snapshot bytes. The kernel files are legitimately mutable; snapshots are published immutably through the shared no-clobber anonymous-file primitive and kept as reviewed raw evidence. Failed publication/late check produces no usable observation. [Namespace visibility](https://man7.org/linux/man-pages/man7/cgroup_namespaces.7.html)

## 5. Stable serial claim lifecycle

Claim mechanism tag0 and overlap serial0 suffice. Every cooperating Task54 runner/campaign on the physical host uses the SAME provisioned lock inode; no campaign-local lock that permits accidental overlap. Fresh `LOCK_EX|LOCK_NB` acquisition: busy means resource-busy/missing current claim, with no polling, stealing, stale cleanup or PID kill. The File description is never duped/exported; CLOEXEC and ProcessStamp checks are mandatory. Forked children may inherit a description, so source must prohibit live-owner use after fork and ensure only controlled exec helpers run; inherited descriptors must not enable release/continue by a child. Drop-only close, no explicit unlock from arbitrary cloned ownership. Kernel flock is advisory and associated with the open file description; duplicated descriptions and fork therefore require real native tests. [flock semantics](https://man7.org/linux/man-pages/man2/flock.2.html)

Lock parents are non-writable to runners. Never delete the stable lock, even after a crash. Recheck original inode/ancestors/mount/process at every boundary. Root replacement of an active lock would split exclusion; provisioning policy forbids replacement while any run is active, and any observed replacement invalidates the owner. This is an administrative prerequisite, not a check/use unlink defense. There is no runner pathname deletion at all.

## 7. Cost and stopping conditions

Chosen serial lock minimizes the new mutable state: one provisioned immutable inode, one held kernel lock, immutable evidence files and no stale-claim garbage collection. Cost is serialization across campaigns and trusted host installation/native verification. A multi-claim allocator would need concurrent reservation arithmetic, crash/currentness/reclaim rules and additional race tests; defer unless actual overlap is required. CPU-only observer/model scope is explicit missing coverage for GPU/external, not removal from the paper matrix.

Compiled source rules avoid an arbitrary model language and prevent untrusted reports choosing budgets. Cost is a source/model review when allocation behavior changes. The compiled bootstrap envelope breaks the metadata/model allocation cycle; its proof is currently unfinished, so there is deliberately no numerical pretend-positive path. The structural-root refinement avoids both hidden-limit omission and false zero evidence. New closed report grammars need an independent oracle; their details must be settled before encoding, not in a permissive implementation.

No source or runtime may begin from this proposal as though ratified. Required design decisions are the three rulings above; required evidence is actual bootstrap and full22-component model validation plus current observer/claim support.
