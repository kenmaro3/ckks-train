## Decision and required rulings

Use **one private resource owner**, bootstrapped from the minimal trusted anchor before context/registry/model metadata expansion, retaining a **single stable per-host serial execution flock** from initial capacity check through all owned-resource teardown. It evaluates source-specific compiled allocation rules, checks real Linux capacity, feeds the SAME retained canonical bytes into the existing typed materializer, and only later binds final actual execution applicability. No sixth gate, generic expression evaluator, scheduler, signing service, caller permit or new user approval layer.

Three refinements require independent design review before source/encoder changes:

1. **Resource exclusion versus publication flock.** Accepted live-gate proposal §5 requires a cooperative claim through crypto teardown; custody §5 says Quick executes with “no flock held.” Specify that publication/profile guards are released during HE, while this distinct host resource flock remains held. Without that explicit clarification, this selected mechanism cannot be implemented as conforming. Alternative: another kernel-held exclusion mechanism or multi-claim registry; both add lifecycle/race complexity without enabling requested science. Keeping the literal prohibition leaves resource claim implementation missing.
2. **Structural cgroup root.** V2 global root has no `memory.current`/`memory.max`. Do not synthesize a zero-current row or treat a namespace root as global root. Propose `Observation.cgroups` contains every applicable *accounting interface* from the process leaf through its ancestors; `host_raw` additionally proves traversal to the real structural root and records its kernel-defined lack of a local memory limit. Empty is permitted only with proved no applicable accounting interface, including the verified global-root case. This is a semantic clarification of the existing list/empty rule; byte grammar stays unchanged. Alternative: version the outer Resource schema to encode a structural-root variant, costing new goldens/codec work; or refuse such observations until that extension. Until this ruling is ratified, do not claim the proposed root handling satisfies the old literal empty rule.
3. **Closed retained source formats and observation namespace.** Define the small report formats below and store immutable claim/observation artifacts beneath the already trusted Observation root, outside attempt trees. Independent literal vectors must precede encoders. Existing Resource/Requested/Requirements/Observation/Claim/FileRef and Full/Quick formats/caps remain unchanged. These source records explain existing FileRefs; they are not new admission events. If their required inventory cannot fit existing caps, return missing evidence and seek a specific refinement; never truncate.

## 4. Concrete Linux observer

Safe Rust/rustix calls only; reuse retained-root/ProcessStamp machinery after its accepted integration, without adding unsafe or altering shared publisher. No `free`, `df`, shell, arbitrary PID scans, cgroup writes, mount changes, sysctls or allocator reconfiguration. Native support and filesystem behavior need later tests.

- **Origins/topology:** capture actual `/proc` filesystem and own process directory, `/proc/self/cgroup`, `/proc/self/mountinfo`, `/proc/cgroups` for the v1 branch, kernel boot identity and namespace identities; v2 controller origin comes from the verified global root `cgroup.controllers` and applicable directory interfaces, not `/proc/cgroups`; open cgroup mounts through trusted held ancestors matched to the actual mount table. An apparent `/` in a cgroup namespace is not proof of the host root. Host policy/launcher must establish actual initial host namespaces; hidden ancestors or unverifiable mount-root mappings refuse. Recheck boot/ProcessStamp, membership, mount mapping and root identities around each observation. Bound all raw reads by8MiB, paths by existing4096, source/list counts by existing limits; use checked conversion and EOF/growth detection rather than procfs st_size. Oversize/unknown/permission/I/O/parse/topology errors mean missing observation, no retry-until-pass loop.
- **Host:** read exact `/proc/meminfo`; require one well-formed `MemAvailable` in kB, checked×1024. Never substitute MemFree/swap or add cached memory again. Bracket the controller read with two meminfo reads and use the smaller observed MemAvailable; retain both. This is still a kernel availability estimate, not reserved RAM. [Linux meminfo manual](https://man7.org/linux/man-pages/man5/proc_meminfo.5.html)
- **V2:** determine the actual memory accounting domain, walk *every* ancestor to the verified global structural root. Read `memory.max` (`max` alone means unlimited) and `memory.current` for every applicable non-root accounting interface; keep the exact ordered paths/raw values, even unlimited ancestors. Check controller placement/domain metadata, never silently omit a parent because the leaf has a limit. Reread limits/topology after the pass; changes refuse. Counters may change, so no atomic-snapshot claim. Threaded/domain-invalid or unsupported placement stays unavailable until its concrete mapping is validated. Root-interface absence follows ruling2, not ENOENT-as-unlimited. [Kernel v2 interface](https://docs.kernel.org/admin-guide/cgroup-v2.html)
- **V1/hybrid:** resolve the hierarchy actually carrying `memory` from own membership+mount/controller records; walk all applicable ancestors and retain `memory.limit_in_bytes`, `memory.usage_in_bytes` and required hierarchy/config facts. Normalize unlimited only from the exact supported kernel/page-size implementation, never “very large means unlimited.” V1 usage batching/kernel-accounting variations require a validated observer profile; absent that evidence, report unsupported v1 observation rather than relabel it v2 or use host capacity alone. V1 docs themselves warn about age, so kernel source-specific validation is mandatory. Hybrid topology must prove which hierarchy owns memory; no guessed union or dropped controller. [Kernel v1 documentation](https://docs.kernel.org/admin-guide/cgroup-v1/memory.html)
- **Capacity:** min(host MemAvailable, every applicable finite saturating(limit−current)); add other cooperative reservations under the Claim semantics below. Exactly existing comparison, no extra headroom constant. Current readings can race noncooperative consumption or host limit changes after observation; every required allocation/update boundary rechecks. A successful comparison is prospective evidence under those checks, never immunity to OOM. Later allocation failure is failure, not retroactive resource skip.
- **Disk:** `fstatvfs` on retained actual observation/output/log/source roots, not arbitrary path strings. `bavail×frsize` with checked arithmetic gives unprivileged free bytes; retain syscall fields and filesystem identity. Model actual additional retained/output/log/temporary publication bytes and needed inode count per volume, plus preservation of existing bytes. Enforce inode availability as a concrete storage prerequisite. Multiple filesystems fit existing scalar wire conservatively: required_disk_bytes=sum of per-volume needs; disk_available=min actual per-volume available; retain exact per-volume map in disk_raw and perform each volume's own check too. No double counting of already consumed blocks as future need. Quotas/remote/overlay/tmpfs or unsupported filesystem accounting require validated quota/backing-memory evidence; `f_bavail` alone cannot prove an unobserved quota. [fstatvfs manual](https://man7.org/linux/man-pages/man3/statvfs.3.html)

Use one bounded topology-bracketed observation pass, with explicit begin/end clocks and raw hashes. Do not demand usage counters remain equal, manufacture a nonexistent atomic instant, or introduce an arbitrary observation TTL. Immediately use the result at the named boundary; any intervening allocation under this owner is charged, any context/claim/topology change refuses. Namespace and interface origin checks are distinct from comparing immutable snapshot bytes. The kernel files are legitimately mutable; snapshots are published immutably through the shared no-clobber anonymous-file primitive and kept as reviewed raw evidence. Failed publication/late check produces no usable observation. [Namespace visibility](https://man7.org/linux/man-pages/man7/cgroup_namespaces.7.html)

## 5. Stable serial claim lifecycle

Claim mechanism tag0 and overlap serial0 suffice. The lock is scoped to the trusted participating account on the physical host; all its campaigns/checkouts use one host-key under its retained account anchor. No campaign-local path, ambient HOME/XDG override or new lock per checkout. Safe ancestors are UID0 or effective-UID owned and not group/world writable; private directories are effective-UID0700; the stable file is effective-UID0600, regular, one link, correct supported local mount. Initial establishment uses exclusive creation and durability checks outside a running claim; an existing validated file is reused, never reset. Concurrent creators resolve to that same inode or refuse. There is no sudo, administrator-created `/run` directory or new approval service.

The trusted account/launcher and compliant runners must not replace/unlink/rename this inode or its ancestors while any claim may exist. Identity checks detect observed changes but do not defend against arbitrary malicious same-UID namespace mutation; that is outside this cooperative mechanism's trust boundary. Other users are not physically excluded from RAM by either a user or UID0 lock. Host-origin proof is separate: independently trusted direct-host evidence establishes the boot/initial namespaces/global cgroup root. A user-owned lock proves none of these, and absent origin evidence remains precisely missing observation.

Fresh `LOCK_EX|LOCK_NB` acquisition uses a fresh file description: busy refuses without polling/stealing/PID actions or attempt writes. The parent descriptor normally remains CLOEXEC. Lock order is resource first, then short profile/publication guards; nested readers borrow the current resource owner and never reacquire the resource lock. The one controlled inheritance exception below preserves the same open file description while helper work survives. Kernel flock is advisory and associated with that description. [flock semantics](https://man7.org/linux/man-pages/man2/flock.2.html)

**Concrete helper-tree crash custody (FIX1):** BASE `context.rs:867–928,1074–1089` spawns `scripts/study_reference_build.py` modes `hash-file`/`snapshot`; snapshot calls support `verify_runtime_snapshot:1153` → `source_inventory` → `git_state:816`, with Git launched by `bounded_run:800`. - The private Rust launcher obtains a narrowly scoped `File::try_clone` of the held resource description and maps it through safe `Stdio::from(File)` to child stdin, replacing the current DEVNULL for these runtime modes only. Rust's std process implementation performs child-fd mapping; no project `pre_exec`/unsafe is added. The clone is an internal hold only, not a cloned ResourceOwner or gate. The parent closes its temporary clone after spawn; child fd0 deliberately survives exec and already holds exclusion during Python startup.

The runtime-only launch binding is the literal `--resource-hold-stdin` plus decimal expected device/inode values from the parent-held FD, parsed strictly and checked against fstat(0); these are child continuity checks, not evidence records or authority. They are supplied only by the private parent helper command after live owner validation. A caller-supplied descriptor/pass flag cannot construct parent authority. Original fd0 remains valid until the duplicate exists. Python shutdown closing stdin therefore cannot release the last helper hold early.
- Runtime `bounded_run` explicitly passes this hold via `pass_fds=(hold_fd,)` to every Git child while preserving DEVNULL for Git stdin. This overrides Python's default close-fds behavior for exactly one FD. Git receives the SAME locked description, inheritable across any allowed exec descendant. No other descriptor is exported. Build/capture/Cargo helper modes are not accidentally brought into this runtime route.
- The closed snapshot commands at BASE are `rev-parse --show-toplevel`, `rev-parse HEAD`, `diff --no-ext-diff --quiet HEAD --`, `ls-files --others --exclude-standard -z`, and `ls-files --stage -z`, with existing config disabling fsmonitor/untrackedCache. Pin/review this behavior and validate the actual executable; do not assume arbitrary Git builds/hooks/plugins comply. An unproved descendant path is specifically unsupported, not silently classified as noncooperative. The helper changes require normal source/build provenance renewal later.
- Parent death after exec leaves Python's hold; Python death while Git lives leaves Git's hold; any permitted descendant likewise retains exclusion until its exit. Normal parent wait is not the safety mechanism. Existing owned-child error handling may terminate/wait only its own child handle; if a descendant survives, its hold keeps a competing runner blocked. No process scanning, PID reuse inference or arbitrary kill/cleanup. A child has no continuation of the parent's context/frame. Possession of the inherited FD technically permits LOCK_UN, so the exact trusted helper/Git code is required never to issue it or convert/close the last hold before covered work ends; this is a reviewed cooperative code obligation, not kernel-enforced privilege separation. The later native controls check that actual contract.

After bootstrap/operation selection, create private claim_id and immutable claim.json in an exclusive observation directory. No mutable current-claim path or stale-record cleanup. The original parent hold and every helper inheritance use one open file description; this, same context/process checks and exact claim origins establish live currentness. New immutable observation sequences do not replace the claim. Final Train Resource points to it; preparation-only work never emits Resource gate evidence.

`other_claimed_host_bytes=0`/`other_claimed_disk_bytes=0` is justified only for this closed participating serial domain, including the helper tree. Serial execution is allowed where consistent with actual user scope; this proposal adds no overlapping execution mode.

Destroy all covered parent resources before closing the parent's lock last. Successful fresh acquisition proves no remaining holder in this cooperative domain, not that every old process is dead. ## 7. Cost and stopping conditions

Chosen serial lock minimizes the new mutable state: one stably established ordinary-user inode, one held kernel lock, immutable evidence files and no stale-claim garbage collection. Cost is serialization across the participating account's campaigns, ordinary-user stable-file establishment, independent host-origin evidence and native verification; no administrator installation is needed. A multi-claim allocator would need concurrent reservation arithmetic, crash/currentness/reclaim rules and additional race tests; defer unless actual overlap is required. CPU-only observer/model scope is explicit missing coverage for GPU/external, not removal from the paper matrix.

Compiled source rules avoid an arbitrary model language and prevent untrusted reports choosing budgets. Cost is a source/model review when allocation behavior changes. The compiled bootstrap envelope breaks the metadata/model allocation cycle; its proof is currently unfinished, so there is deliberately no numerical pretend-positive path. The structural-root refinement avoids both hidden-limit omission and false zero evidence. New closed report grammars need an independent oracle; their details must be settled before encoding, not in a permissive implementation.

No source or runtime may begin from this proposal as though ratified. Required design decisions are the three refinements above as corrected by these four FIX1 resolutions; required evidence is actual bootstrap and full22-component model validation plus current observer/claim support. Once present, proceed with SAME-bytes typed materialization and original five-gate lifecycle; do not add a generic approval layer or rewrite the experiment scope.
