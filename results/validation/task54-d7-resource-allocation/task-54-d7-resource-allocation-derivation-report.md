## Notation and physical-accounting boundary

Let `N` be ring degree, `S=N/2`, `q=Q.len=L+1`, `p=P.len`, `d=dnum`, `alpha=q/d`, `r=l+1`, and `D(l)=floor(l/alpha)+1`. For the registered constructor above both presets have `N=2^16,q=32,p=4,d=8,alpha=4` (`params.rs:12–58,159–183`); their prime bit values differ. NI compute output level is16 and initial expanded state starts at15; retain exact stage/step levels from planning instead of assigning every object level31. No constructor was called to obtain these constants. These constants do not imply a universal parameter bound for every matrix role.

Use `P(r)=8*N*r` for **coefficient payload** of one RnsPoly, `Q(l)=P(l+1)+P(p)` for a QpPoly at level l, `C(k,l)=k*P(l+1)` for a k-component ciphertext, and `K(l)=2*D(l)*Q(l)` for a stored switching key whose parts are generated at level l. These are logical scalar payloads only. Normally stored ciphertexts have k=2; unrelinearized intermediates have k=3. Record actual k and level for each lifetime.

The requested backing layout of one polynomial is instead `cap_outer*sizeof(Vec<u64>) + sum_j cap_j*sizeof(u64)`, plus its inline RnsPoly object **where that object is actually stored**. The latter contains an Arc handle, Vec handle and form flag. The shared basis allocation is counted once in16, not once per polynomial. Capacities, object sizes/alignment, padding and allocator rounding remain symbolic, dependent on pinned Rust/std/dependency/target/allocator proofs. `vec![..]`, `collect`, `clone`, `with_capacity`, `try_reserve_exact` identify allocation requests and live lengths; they are not a platform-independent maximum capacity guarantee. Nested Vec headers are real allocated elements. `pop`/`clear` drop elements but retain the outer allocation; freed heap blocks may remain allocator resident (19).

Every deep copy of `RnsPoly`, ciphertext, SecretKey/PublicKey or Encoder has separate element backing; Arc clones alias the same pointee. Assignment/move of Vec/RnsPoly transfers ownership without coefficient copying. When replacing an old value with a fallible new value, old and completed new allocations coexist until assignment/drop. Error propagation drops owned partial results but does not prove memory has returned to the OS.

Existing phase bits are **1 prepare,2 key-setup,4 update,8 endpoint** (format contract §3). The table's phase letters P/K/U/E describe source lifetime/work, not a finalized numeric mask. Lifetime retained across a phase remains chargeable there even if it performs no new allocation. Cross-phase absolute/incremental maxima still use existing Requirements; this report computes no sums. No residency credit is asserted: a same-observation proof is required to classify an allocation as already charged, and dropped objects do not justify credit. Conservatively retaining proved live terms as additional is the accepted architecture; unknown terms still refuse.

## Core allocation and lifetime derivation details

### Key generation and key owners (0–4)

`RnsPoly` is derived Clone over `Vec<Vec<u64>>` and one Arc (`core/poly.rs:24–28`). Its `zero` allocates one outer vector and r distinct N-word vectors (55–65); from_limbs consumes vectors and clones only the basis handle (70–101). `keys::truncated` at even the SAME level clones, and below it `[..=level].to_vec()` clones each limb (153–167). Therefore secret at_level, public q_at_level, and equal-level alignment cannot be charged as borrowed views.

Ternary sampling (`sampler.rs:110–139`) holds N i64 coefficients. Sparse h adds N usize Fisher–Yates indices, but that index Vec's branch scope ends before signed_to_poly; do not claim its backing returned to OS. Dense sampling has no index allocation. signed_to_poly emits r separate N u64 limbs. `small_qp` moves Q and creates p new N-word P limbs from Q limb0, then NTTs in place (`keys.rs:627–658`). Gaussian sampling (sampler166–187) retains CDT and N i64 coefficients while producing Q limbs. The key error sigma is3.2 (keys85), so the CDT logical count is `2*floor(6*3.2)+1`; its constructor intermediate weight Vec and all capacities remain in scratch inventory, not an unbounded MAX_GAUSSIAN_SIGMA substitution for this callsite.

Public/RLWE construction (`keys.rs:486–514`) first creates aq/ap (`Q(l)`), then e as another QpPoly. It clones a to construct bq/bp, so a+e+b can coexist before return; Q at_level truncation of a sparse target additionally allocates P(r) when target remains full. Return moves a/b and drops e/truncation. A switching-key iteration (`522–565`) keeps all previous completed parts, creates current `(b,a)`, then constructs a FULL r-limb gadget even though only one digit is nonzero: zero branches allocate `vec![0u64;N]`, not absent limbs. Thus the current pair `2Q(l)` and gadget `P(r)` overlap; do not model gadget as alpha limbs. The parts vector requests D(l) pairs. Relin's extra s² or rotation's sigma(s) source stays during the whole ksk construction. Permutation caches persist with basis16, not temporary source0/3.

SSE (`435–466`) samples a full-QP sparse secret, constructs to_sparse first at level0 (one digit), then to_dense at full L while the sparse secret and to_sparse coexist. `sse_keys(...).map(|(k,_)|k)` drops the ephemeral secret only after both are complete. Final payload `K(0)+K(L)` must not be replaced by two full keys or two level0 keys. Main generator still lives during this process.

`make_material` order is Encoder → optional Bootstrapper → public encryptor → copied secret decryptor → relin → training rotations → cloned client Encoder (`study_client.rs:411–465`). Bootstrap keys are not drawn from or aliases of the later training Galois map. At the end of make_owned_fields (`832–842`) main generator drops; returned client/context retain all other owners. I execution creates refresh service later and deep-copies public/secret/Encoder (`694–702`), then session borrows the service. `cpu_continuation.rs:186–315` ensures session before refresher before client/evaluation before retained inputs on normal and error exits.

### Compact, expanded, optimizer and packet states (7–11)

For layer j, let `L_j=max(pow2(out_j),pow2(in_j))`, `m_j=min(pow2(out_j),pow2(in_j))`, capacity in compact positions `a_j=S/L_j`, and `w_j=ceil(m_j/a_j)` (`compact.rs:96–135`). Container count `W=sum w_j`, `T=W+b`; construction temporarily holds used bool vectors of a_j entries per container, candidate Vecs and sorted choices. Their physical bool/Vec layout and sort scratch require std/target evidence.

### Bootstrap construction/workspaces and serial worker work (4,12–13)

Bootstrapper::new holds raw cts/stc DiagMatrix lists, encodes CtS then StC, then calls BootstrapKeys::generate, which calls stages AGAIN (`bootstrapper267–273,104–111`). Thus the first raw lists plus both encoded transform lists overlap the second raw lists during key generation, and grow with completed keys. A raw DiagMatrix owns BTreeMap nodes and one S-entry Complex64 Vec per stored offset (`linear78–81`). Adaptation uses rho/scaled/conj_sandwich and creates independent matrices (512–555). `window` creates shape.d full S-entry vectors, including explicit zero slots and cloned stored diagonals (259–277); sparse encoding omits polynomial payload only for actual all-zero diagonals, not the Option entry array or preceding dense windows/pre-rotation buffers. Final stored transform payload is `sum_{stage,main/second} nonzero_diagonals*P(stage_level+1)`; CtS level starts L, StC starts levels_after_boot+stoc_levels (bootstrapper217–235). Exact number of nonzero diagonals and maximum map node/window overlap across registered BootParams remains a source-sizing obligation; comments saying “about13GB” have no role in this worksheet.

Bootstrap pipeline (`bootstrapper405–430`) retains raised output and CtS real/imag pair while evaluating two EvalMods; join is `(a(),b())` in serial builds and Rayon join in parallel builds (`par43–57`). Even serial execution retains the first returned Result while evaluating the second. Shadowed earlier owners must not be assumed dropped at last read; bound their lexical/drop scope or prove a narrower compiled lifetime. Test trace extends cloned intermediates only when the test-only caller supplies trace; production passes no trace. Do not include test observation allocations as production behavior, or claim their absence removes ordinary temporaries.

Cheb owns a BTreeMap of cached ciphertext powers; each power i has level `top−ceil(log2 i)` (`poly488–530`). `ensure` recursively retains prerequisite powers and constructs aligned ta/tb, a 3-component multiplication, relinearized/doubled/constant-adjusted products and rescale output before insertion. rec splits coefficients into q/r Vecs, retains qres while computing rres and then combines them (`535–569`).
