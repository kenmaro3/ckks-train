# Study training bridge: diagonal CPU/CUDA execution

**Status: INDEPENDENTLY REVIEWED AND ROOT-RATIFIED DESIGN — Task54 D2c/D3; individual implementation packages and campaigns require their separate gates.**

This proposal connects the 21 registered profiles and 17 families in [the experiment matrix](experiment-matrix.md) to a new study executor. It specifies main diagonal CPU/CUDA interactive and noninteractive training, including WN/AU/AA and independent block stages. It establishes neither implementation coverage nor permission to execute a campaign. D2a's fixed-reference interactive NAG API is independently reviewed at `8c8c7bc`; D1/D3a provide data loading and canonical AA handoffs. D2b1's [input contract](study-profile-inputs.md) is the input boundary, subject to its final independent review. No historical binary, FULL command, raw result, baseline source or scientific threshold is changed.

## 1. Recommendation and scope

Add `crates/ckks-train-bench/src/bin/study_train.rs` as a thin frontend over small public bench modules. Leave `src/bin/mnist.rs`, its `mnist/blocks.rs` helper, `iris.rs`, `plain.rs`, `twin.rs`, historical CLI defaults and output formats intact. The new frontend requires an explicit registry profile, statistical seed, family/role, backend, mode and placement; it rejects incompatible combinations before HE allocation. Its outputs use a new versioned study schema and distinct paths. It must reject FULL control IDs and historical output destinations.

| Option | Benefit | Cost / decision |
|---|---|---|
| New `study_train` and shared modules | One resolved graph/data contract for all datasets, two numerical reference types and future packing adapters; testable admission and measurement boundaries | A new CLI/schema and some orchestration coexistence; recommended. Reuse stable public NN/backend primitives, not copied legacy loops. |
| Expand the roughly 4,000-line `mnist` binary | Reuses existing command plumbing | Hard-coded ten-class/graph/config assumptions and intertwined modes risk FULL regressions; would need the same modular work while expanding compatibility obligations. Rejected for this bridge. |
| Immediately extract legacy binaries onto new modules | Eventually reduces duplicate orchestration | Changes historical arithmetic/order/timing behavior before new equivalence evidence exists. Defer to a separate compatibility task. |
| Per-dataset executors | Small initial code patches | Duplicates initialization, schedules, tails and checkpoint logic; does not solve faithful block/F32 pairing. Rejected. |

The diagonal executor does **not** implement CPU2020 row packing, prove a faithful CPU2020 diagonal baseline merely by using the same graph, implement packed-c, or run official ReBoot. Baseline-a needs an explicitly matched row/2020-diagonal adapter and packing/count review. D4 owns alternating row/column encrypted training separately, including its geometry/primitives in `ckks-train-nn/src/packed_training/`. D5 owns the external executable/config/export adapter and same-host/thread receipts. Their shared input access is defined below; absent adapters remain `MissingCode`, absent official dataset/profile/seed exports remain `MissingInput`. No GPL source is imported. ReBoot eMLP2/3 baseline-b remains outside the registered hardware scope; main and packed-c block cases remain applicable.

The D0 family expansion has168 main +10 baseline-a +84 packed-c +6 external-b =268 quick family cases, or2680 full family cases over ten seeds, before supplements and plaintext references. A validated baseline-a diagonal case may be a role alias of an exactly matching main2020 CPU observation. Preserve both coverage roles and a shared measurement ID; do not count reused evidence as an independent run/statistical replicate. This proposal does not implement that D7 expansion or assert that268 cases are executable today.

## 2. One pure input materializer, two numerical precisions

Current concrete API is `StudyRegistry::load(root).resolve(id, seed) -> ResolvedProfile`. `metadata()` describes a graph and recipes; `preflight(None)` verifies captured/source bindings and a `BatchPlan`, **not dataset bytes**. `prepare_dataset() -> PreparedDataset { dataset, inputs }` performs the combined source-lock, dataset-hash, canonical preprocessing/split and captured-input checks. The approved registry and portable input-lock SHA pins are inputs, never regenerated from current files during a run. The name `PreparedProfile` in earlier planning is conceptual, not an existing Rust type.

Proposed public contracts in `src/study_inputs.rs` (names below are proposed APIs, not implemented claims):

```text
materialize(resolved: &ResolvedProfile)
    -> Result<MaterializedProfile, StudyInputError>

MaterializedProfile {
    metadata: ProfileMetadata,
    graph: StageGraph,                 // named layers, stages, loss barriers
    dataset: Dataset,                  // canonical F64 D1 arrays and labels
    initial: InitialModel<f64>,        // logical out-by-in, owned zero/active biases
    order: MaterializedOrder,          // canonical training-row indices, epoch offsets
    plan: BatchPlan,                   // exactly D2b1 updates/checkpoints
    identity: MaterializedIdentity,    // immutable source + array/order/recipe hashes
}
MaterializedProfile::numeric_f32() -> Result<NumericInputs<f32>, StudyInputError>
MaterializedProfile::numeric_f64() -> NumericInputs<f64>
MaterializedProfile::update_rows(index) -> Result<UpdateRows, StudyInputError>
```

The public production `materialize(&ResolvedProfile)` calls `prepare_dataset()` exactly once internally and immediately consumes its result into a private `MaterializedProfile`; it accepts no caller-supplied mutable `PreparedDataset`. It validates dimensions/classes/train/test indices and plan/order consistency during that consumption. Root rejected a public two-argument alternative: source hashes and matching dimensions cannot prove the numerical arrays in the publicly mutable D2b1 result were not altered after loading. A lower-level assembly helper stays nonpublic; fixture entry points, if needed, require an explicit synthetic/non-scientific type that cannot be promoted to production readiness. There is no duplicate dataset load or recipe generation. New validated constructors keep fields private and expose immutable views. `StageGraph` binds layer names/roles to slices in one canonical parameter order: each local forward layer, its local head, then the next block, finally output hidden/output. No adapter regroups weights by width or guesses stage membership. `UpdateRows` includes the exact `PlannedUpdate`, row-index slice, optional pass identity and crossed boundaries; it never reshuffles or independently recomputes rates.

`MaterializedIdentity` retains expected and actual source digests, registry/portable-lock identity, dataset/split/preprocessing identities, selected seed, source orientation, recipe version and code/build identity. It additionally hashes logical arrays, bias arrays, flat consumed order and plan with a documented encoding: named/typed fields, explicit dimensions, little-endian IEEE bits and fixed-width indices in row-major order. It records both pre-cast F64 and derived F32 hashes with `round-to-f32-once` provenance. A content digest proves shared inputs, not upstream attestation. Missing eMLP2/3 seeds3–9 fail without initialization/order substitution; locally initialized MNIST2020 consumes its explicitly borrowed verified order/schedule and generates its own weights.

**Initialization is generated exactly once.** Captured preflight matrices already have logical `out × in` orientation; do not transpose a second time. Local recipes implement the exact [D2b1 RNG/draw contract](study-profile-inputs.md): new ChaCha20 streams `[role, seed, seed, ...]`, roles1–5; Normal sigma0.2 uses the documented 53-bit uniform, Box–Muller cosine and enabled bias draws; Xavier uses `sqrt(1/(fan_in+fan_out))`, consumes/discards disabled bias draws, and materializes disabled biases as zeros. Exact Iris uses the legacy master/fork sequence and in-place epoch permutation. Persist the init/shuffle streams; do not reseed per layer, batch or epoch. The materializer can call already matching pure `twin::rng/uni` primitives, but only one new routine owns recipe traversal. CPU, CUDA, plaintext and future baseline adapters consume its arrays, never call their own initializer.

**Order is independent of encryption randomness.** Captured48000-index orders are consumed once; local orders use the specified per-epoch Fisher–Yates, fixed split and tail policy. Iris preserves its preceding-epoch permutation; new recipes start each epoch from canonical rows with a persistent shuffle stream. WDBC shuffles all455 rows then retains448, dropping7 per pass. Keep source row indices separate from indices into canonical D1 training arrays. The materializer validates the entire order against D2b1's plan before HE setup; full Fashion order may use checked `u32` row IDs plus epoch offsets, without materializing all expanded feature batches. Batch features and one-hot labels are gathered only for the current logical update.

**F32 is an actual computation.** `src/study_plain.rs` provides `PlainState<T>`, `step_plain<T>` and `evaluate_plain<T>` for precisely `f32` and `f64`. A narrow scalar abstraction shares graph/update control flow; products, activations, reductions, deltas, gradients, velocity, rate/momentum arithmetic and parameter updates stay in `T`. No internal conversion to F64, no `twin_step` F64 wrapper followed by an F32 cast, and no backend-dependent fused algorithm selected silently. Declare reduction order and accumulation dtype in provenance. Cast the already approved D1 preprocessed data and canonical initial arrays once; do not re-fit preprocessing in F32 or generate fresh weights with F32 RNG math. Compute the integer correct-count first, then emit its exact denominator and F64 reporting ratio. Retain nonfinite numeric outcomes as explicit failures. The F64 instance is the parity diagnostic; the F32 instance supplies the new target artifact. Existing `twin.rs` remains a historical eMLP-specific F64 reference, not the generic Square/SGD engine.

## 3. Exact learning graph and rate contract

| Model | Independent stages | Activation / labels / bias | Update |
|---|---|---|---|
| `mlp2020` | `[input,10,C]` | Square then Square; exactly `C` logical outputs; active Normal-initialized biases | Mean sample/real-class MSE, derivative `2(pred−target)/C`; SGD |
| `emlp1` | `[input,32,P]` | PolyRelu2 (`z²+z`) then Identity; zero target in padded trainable channels; zero frozen biases | RSS delta `pred−target`; NAG momentum0.9, decay0 |
| `emlp2` | `[input,64,P]` local stage; `[64,32,P]` output stack | Each stage PolyRelu2 then Identity; independent targets/loss; no gradient crosses stage boundary | Same NAG, persistent independent velocity per layer |
| `emlp3` | `[input,128,P]`, `[128,64,P]` local stages; `[64,32,P]` output stack | Same independent local heads; inference ignores those heads | Same NAG |

`C` is3/2/10/10 for Iris/BC/MNIST/Fashion; eMLP `P` is4/2/16/16. A logical eMLP padded channel participates in initialization fan-out and loss. Layout padding beyond the logical width does neither. Use `profile_data::padded_targets` for the declared output width and `class_accuracy`/its F32 equivalent with argmax restricted to `0..C`; never use a ten-class constant. Reject inconsistent labels/widths before encryption.

Use D2b1's `PlannedUpdate.mean_gradient_rate`, `delta_multiplier` and selected schedule index as authoritative. Captured schedule lookup is `floor(processed_start/48)` over the flat stream, including B64/B128. For RSS, mean rate is source sum coefficient times **total valid logical samples**, not physical lanes or each microbatch's size. Exact Iris mean-MSE rate stays0.1. Adapted2020 uses its fixed nominal logical batch conversion. No constant-rate replacement, restart approximation or extra factor2 is allowed.

Current NN trainers start from `Mse.grad = pred−target`. For this registry, avoid a new loss implementation: fold the constant `delta_multiplier` into **both** weight and bias optimizer coefficients by supplying `kernel_lr = mean_gradient_rate × delta_multiplier`. In the plaintext reference apply the explicit loss derivative and original mean rate, providing an independent equivalence check. All registered multiplier≠1 cases are SGD; eMLP NAG has multiplier1. Record the two semantic fields and derived kernel coefficient separately, so a rate is never mislabeled as a changed learning problem. A future varying loss factor is not admitted by this proposal. A future fixed-factor NAG profile would need both current/reference coefficients consistently transformed and explicit velocity-basis validation.

For each NAG stage/layer choose one finite positive `reference = max(kernel_lr over the FULL prepared plan)` **before boxing/velocity initialization**, including quick runs which consume only two updates. This preserves the full-profile reference-gradient path in quick. Check finite/positive mean rates, loss factors and derived products, including reference/momentum folded constants, before HE setup; overflow must not survive a finite-input check. Build each `Nag` with the first rate, set its reference, then box it for `Trainer`; configure NI reference before its first update. Never reset velocity at a rate change. NAG semantics are `V' = μV+g`, `W'=W−lr(g+μV')`; encrypted state uses D2a's fixed reference basis. Apply frozen-bias builders on **every** eMLP stage before the block wrapper is assembled. Zero biases retain ordinary encrypted bias operations and refresh counts.

## 4. Admission: all graph shapes, explicit physical plans

`src/study_admission.rs` proposes `plan_diagonal(&MaterializedProfile, &CaseSpec) -> Result<DiagonalPlan, AdmissionIssue>` with no key generation or evaluator training. `CaseSpec` is checked against registered family axes; main I uses `n16_train`, main NI uses `n16_boot`. These secure presets have32768 slots. The planner preserves logical dimensions and chooses one common `Layout` across block stages, as current `BlockTrainer`/`BlockNiTrainer` require. It computes `d = max(next_power_of_two(each stage input/output))`, with `lanes` a power of two and `d×lanes` dividing slots.

| Registered population / graphs | Common d by graph (`2020`, `e1`, `e2`, `e3`) | Default physical lanes | Valid samples per logical update |
|---|---|---|---|
| Iris |16,32,64,128|32|20;6 updates/pass,400 passes|
| BC |32,32,64,128|16|16;28 updates/pass,100 passes;7 dropped/pass|
| MNIST196 B48, all graphs |256,256,256,256|64|48;100 updates/pass,10 passes|
| Fashion196 B48, all graphs |256,256,256,256|64|48;1250 updates/pass,50 passes|
| MNIST196 B64, all graphs |256,256,256,256|64|64;75 updates/pass,10 passes|
| MNIST196 eMLP1 B128 candidate |256|128|128;375 updates over flat48000 rows|

These are **candidate geometries**, not completed admission proofs. In particular256×128 fills the input layout but does not prove B128 training/level/memory readiness. Retain all21 profile IDs and all family axes in the coverage ledger even when a candidate fails. Other slot-maximal logical batches require separate registration; the table does not claim those maxima.

`DiagonalPlan` must contain a per-stage proof receipt: logical/padded layer dimensions; every `LayerShape` diagonal count/period and BSGS split; canonical activation/bias/target widths; lane masks; transpose strategy; compact weight/bias/velocity container occupancy for NI; stage `BatchSpec` levels/scales; full and partial gradient/activation level traces; refresh/bootstrap output and downstream handoff requirements; and the maximum simultaneously live ciphertext set. Use `Layout`, `CompactLayout`, `mlp_rotation_steps`/`ni_rotation_steps`, block key helpers and `TransposeKeys` semantics, with complete checked input validation before panicking shape constructors. Union and deduplicate rotation keys across all stages, gradient reductions/replication, compact repacking and bootstrapping, with exact parameter/level identity. Budget keys before allocation. Do not derive a proof solely from `d×B≤slots` or borrow eMLP1's depth for Square/Square.

Pure metadata/level arithmetic is the pre-key gate. Existing executable probes are isolated from training counters and checked against this plan after construction; disagreement is a planning failure. The static planner must model first NAG update, later velocity updates, reference-gradient on/off, partial constant-derivative masking, WN current/next-full decisions, AU and AA separately. Unsupported arithmetic/shape is `MissingCode` or `LayoutUnproved`, not a falsified negative capacity result.

### Logical batches and future capacity fallback

`MicroBatchPlan { update_index, physical_lanes, parts: [(row_start,n_valid)], total_valid }` partitions one update into ordered nonempty pieces, validates `sum(n_valid)=PlannedUpdate.valid_samples`, and never crosses into another logical update. Defaults above need one physical ciphertext batch. B48 in64 lanes has48 valid/16 inactive lanes on **every** update; Iris20 in32 likewise remains partial. Validation includes final retained tails in general, even though current Iris/Fashion counts are divisible and captured flat B128 has no tail. Dropped BC rows are not zero-filled fake samples.

An explicitly admitted capped32 plan for logical B48 uses32+16 and **one** optimizer update, one schedule value and one logical counter increment. It cannot call `train_batch_valid` twice. NI already accepts `train_step_valid(&[(x,y,n_valid)])` and normalizes by the sum. Interactive currently accepts one physical batch only; capped plans therefore remain `MissingCode(InteractiveMicroAccumulation)` until the following independently reviewed extension lands. This missing extension does not exclude the sufficient-lane primary candidates.

Propose `Trainer::train_step_valid` and `train_step_valid_with_hidden` with the NI-style slice API, preserving existing singleton wrappers and arithmetic order. Compute all microbatch forward/backward paths from the **same pre-update weights**, mask inactive lanes, accumulate per-layer gradients with a common denominator `N=Σn_valid`, align mixed full/partial levels before addition, then update each optimizer once and refresh once. For each microbatch use folded coefficient `current_scale/N` (and `reference_scale/N` when required); equivalently sum `n_i/N` times each micro-mean. Never average micro-means uniformly. Bias coefficients use the same denominator. Return hidden activations indexed `[micro][layer]` from pre-update weights. Keep legacy single-batch operations/counts bit-for-bit unchanged. General transactional rollback is not promised; a failed partial update is terminal and cannot be retried as if unchanged.

The784-input `weighted_partial_v1` supplement has padded d1024 and at most32 lanes at N2^16, hence the same32+16 requirement. It remains a separate supplement/profile registration path, not a new22nd primary profile or a change to historical R-M3-4 exclusions. Any memory-driven lane/transpose fallback must be explicit, preserve the logical profile, emit its physical-plan identity and have a validated count/precision model. Do not automatically switch model, optimizer, security, top level, batch or seed. An unsupported fallback is missing code; a queried device with insufficient available bytes for an admitted plan is a resource skip.

## 5. Generic encrypted executors and block bridge

`src/study_diagonal.rs` owns graph-to-`Mlp<E>` construction and `DiagonalSession<'a,E,B>` dispatch over single-stage or block trainers. Public names such as `run_diagonal<E: HeOps, B: BootstrapOps<E>>` are proposed contracts. Backend factories supply evaluator/bootstrap/refresh interfaces; the training core receives encrypted microbatches and public rates/layouts only. Logical parameters are encrypted once via `Mlp::encrypt_at`, NI `encrypt_network` or the block equivalents, after admission. Build `Square`, `PolyRelu2` and `Identity` directly from metadata, not inferred layer position except where metadata explicitly declares it.

`src/study_client.rs` owns encryptors, decryptors, canonical arrays and random streams. It gathers current update rows and generates each stage's one-hot target at **that stage's `BatchSpec.y_level/y_scale`**; equality of logical labels does not imply interchangeable ciphertext scales. It encrypts the first-stage input once per microbatch; later inputs are encrypted handoffs, not decrypted/repacked data. After setup the NI server/session contains no `SecretKey`, `Decryptor`, plaintext dataset/weights/gradients/velocity, or callback that decrypts a training gradient. In-process orchestration is a declared reference transport, not a proof of remote isolation. Interactive client refresh is explicitly different and counted/timed.

Proposed `src/study_blocks.rs` maps `StageGraph` to `BlockMlp`, `BlockTrainer` and `BlockNiTrainer`, not a reimplementation of their forward/backward mathematics. Each stage has its own local loss/optimizer/velocity; all see handoff activations from the source stage's **pre-update** weights. No downstream gradient enters an earlier local block. Plaintext block reference computes all old-weight inputs before updates, independently checking the encrypted stage order.

Two narrow NN extensions need separate ownership/approval before work:

1. **All-stage rate validation.** Expose `Trainer::validate_lr(&self,lr)` plus an infallible post-validation commit path, preserving the D2a contract. Add equivalent read-only validation for NI. `BlockTrainer::set_lr` and hardened `BlockNiTrainer::set_lr` first validate every stage/layer, then commit all. Reference setters are configured on unassembled stage trainers; if a block-level reference setter remains exposed, it too must validate all before any mutation. Current NI block setters use sequential fallible mutation; current interactive block wrapper has no rate setter. A last-stage rejection must leave all earlier rates and counters unchanged. This guarantee covers configuration validation, not rollback of HE/refresh failures mid-step.
2. **Interactive block microsteps.** Add `BlockTrainer::train_step_valid` for `BlockMicroBatch`-shaped input after interactive accumulation is accepted. Each stage consumes all microbatches before its single update; refresh each returned first hidden activation once at a stage boundary. Preserve existing singleton API behavior. Peak memory includes retained handoffs across microbatches; final heads are never passed to the next stage.

NI AA reuses exactly `stage.last_activation_bootstraps()[micro][0]`, already at canonical Delta, with only required downstream mod-switching. `train_step_valid_with_hidden` retains its pre-bootstrap API meaning. No second AA handoff bootstrap, Delta reconversion, client repack or decryption is allowed. WN/AU retain the explicit canonical conversion and one handoff bootstrap per boundary per microbatch. Their counts are additional; AA reuse counts zero additional handoff boots. Keep `last_handoff_bootstraps` diagnostics and existing D3a tests. Bootstrap range requirements remain declared; client diagnostics at declared endpoints may measure ranges but may not clip/rescale training values or silently change the profile.

CUDA instantiates the same core with `CudaEvaluator`, `HostRefresher` for I and `HostBootstrapper` for NI. Host bootstrap uses an independent host evaluator/fork, never the same counter object; its merged counts are already in the device evaluator. Native CUDA bootstrap is a separate adapter/hardware gate. Keep sequential matvec execution; `--matvec batch` remains unsupported. CPU uses the same graph/plans, ordinary client refresher or bootstrapper, and explicit thread receipts. A CPU compile check of generic code is not CUDA execution evidence.

## 6. Memory admission, lifetimes and measurement hooks

`src/study_backend.rs` builds a graph-specific `GpuNeed` from exact key count/levels, tables, all live stage weights/biases and velocity, compact containers, both scheduled-gradient branches, transpose work, current encrypted microbatch inputs and per-stage labels, retained old-weight handoffs and transfer/bootstrap staging. Existing `backend::mlp_gpu_need` is a useful primitive but not a sufficient scheduled/block peak bound. Use checked byte arithmetic and maximum phase liveness, with a documented conservative margin; report estimated host and device components separately. No entire encrypted dataset cache by default. Release finished stage/microbatch intermediates at proved lifetime boundaries; do not silently trade away pre-update semantics to save memory.

Before **any key allocation**, query device availability and compare need/free. Preserve exit3 with a structured `ResourceSkipped {need_bytes,free_bytes,plan_hash}` for actual insufficient capacity. Unknown device availability is an availability error, not an inferred OOM; an allocation/runtime OOM is `Failed`, not a skip. Open/bootstrap/key setup order is recorded. Call synchronized `trim_pool(0)` after key upload, after network upload, and once at every actual update endpoint that crosses a logical epoch boundary (carry **all** boundary IDs in that one event). Apply `PoolPolicy::AfterKeys` only once keys and network are resident. Trim after final cleanup as a separate phase. For B128 do not trim at fractional update37.5 or split its training step.

D6 needs a new measurement interface, e.g. `StudyObserver::phase_begin/end`, `update_begin/end`, `checkpoint` and `memory_sample`. Existing `DeviceHooks::sync/trim` are reused, but `memory_log()` contains current pool use after trims, **not peak**. High-water evidence requires separate supported CUDA pool-used-high, pool-reserved-high and reset/read hooks, with source/version and phase scope; sampled process VRAM has sampling period/PID/device and an explicitly sampled-peak label. Unsupported metrics are null with a reason. Neither current snapshots nor static estimates may fill peak fields.

For one update: encrypt/gather on the client, upload, synchronize; open the server-update interval; execute the complete logical step; synchronize; close it. Inside I refresh and NI host-bootstrap boundaries use disjoint timers for device waits, download, client refresh or host bootstrap compute, upload and upload completion. Device waits caused by previously queued HE work belong to server level work, not client crypto. Existing `SyncedRefresher` wait correction helps preserve this distinction but does not by itself separate transfer/compute or handoff refresh; D6 instrumentation must cover both. Sequential ownership of event spans makes accounting auditable.

Emit both inclusive synchronized step wall time and its nonoverlapping components. Host bootstrap compute is **server** work, not client refresh. `server_step_wall` includes NI host bootstrap and transport internal to that adapter; report components without adding them again to the inclusive total. For I distinguish server-level work, client refresh and transfer explicitly. Setup, data preparation, client encryption, checkpoint evaluation/diagnostics, trim/housekeeping and total end-to-end wall time each have their own scopes. A clock's nesting/additivity is in the schema; aggregation never sums nested parent/child clocks. If fine-grained clocks are not instrumented, report them unavailable rather than infer them from an incompatible legacy timer.

Backend `ev.counter()` snapshots are the source of measured operations. `key_switches = rotations + relins + sse_switches`; bootstrap KS are already included, and `HostBootstrapper` already merges host operations. Do not add `bootstraps × BOOT_KS` to measured KS. Record refresh/handoff event counts separately because they are not bootstrap operations. Actual deltas must include scheduled reference gradients, inactive-lane masks, chosen transpose/replication, compact repacking, all stage bootstraps and explicit handoffs. Snapshot before/after the logical update and after synchronization, without resetting counters inside a case. Use an isolated/forked evaluation path so client reporting cannot contaminate training deltas.

Analytical `PredictedUpdate` is separate, versioned by physical plan, first/later-state condition, rate/reference equality, EvalConfig, full/partial microbatch tuple and placement. Compare it to actual counters in focused tests before marking it validated. Interactive extra reference gradient costs `+m` ct-pt, `+m` rescale and `+m log2(lanes)` replication rotations per layer per microbatch; NI uses its distinct compact-gradient shifts. Do not transplant either formula into the other trainer. No constant-rate simulator is declared valid for schedules without those terms. Prediction failure keeps the observation and marks the model mismatch; it never repairs measured counts.

## 7. Checkpoints, true FP32 targets and provenance

`src/study_metrics.rs` defines versioned cumulative receipts at update0/sample0 after setup and at each D2b1 checkpoint. Include completed updates, actual processed samples, every crossed logical boundary ID, exact-boundary flag, cumulative operation/bootstrap/refresh counts, cumulative clocks by declared scope, memory provenance, correct/test count and accuracy. Setup has a separate baseline and is not charged twice. Quick receipts use their own subset identity and update checkpoints; they do not supply full-profile time-to-target evidence.

For B128 the update endpoints are38,75,113,150,188,225,263,300,338,375; samples4864,9600,14464,19200,24064,28800,33664,38400,43264,48000. Consecutive intervals alternate38/37 updates and4864/4736 samples. D8 subtracts cumulative consecutive receipts: additive interval totals must conserve `final−origin`. Each complete update belongs to exactly one interval. Normalize by each actual interval's samples/updates, not4800. Do not interpolate epoch observations, prorate crossing updates, repeat boundary IDs or pretend first-following accuracy bounds unobserved boundary accuracy. Whole-run total/10 is only an explicitly amortized logical-pass average.

`src/study_reference.rs` proposes `write_fp32_artifact`, `lock_target` and `verify_target_lock`: the full seed0 actual-F32 final artifact fixes `target=max(0,final_accuracy−0.005)`, profile/batch/hash/design revision and lock timestamp before any new paired matrix HE results are examined. Report checkpoint-first crossing as an upper-bound detection time without interpolation; unreached profiles are right-censored at final training time, not assigned zero or averaged as reached. Final accuracy is always the fixed final endpoint. Client model decryption/evaluation is permitted only at declared reporting endpoints outside server timing and never feeds subsequent training decisions; describe the intermediate reporting disclosure separately from a terminal-only NI deployment.

Binary-owned provenance binds case/profile/seed, graph/loss/optimizer/reference rates, full and consumed plan hashes, every input/materialized hash, security parameters/secret distribution/bootstrap path, packing/microbatch/transpose layout, source tree/build/binary identity, argv, host/device/thread environment, measurement schema and target lock. A runner may schedule a case but cannot insert missing measurement provenance or rewrite raw JSON. Incomplete/failed output is explicit and not a successful row. Distinct cases never overwrite an existing finalized artifact.

Preserve all four RQ1 comparisons from [M3](m3-report.md): each side's bootstrap cost (111 measured versus502 modeled in that historical setting), both502, both111, and bootstrap-excluded costs derived from the **same NI run** including compact work. Historical modeled denominators remain labeled modeled; new parameter-specific bootstrap counts are not assumed to be111. Preserve the ratio≤0.70 precision/security/same-CPU wall-clock conditions. FULL-1 stays its original750-update B64 control; FULL-2 stays1000-update B48-in64 seed0 with `abs(acc−0.9041)≤0.005` against its captured twin. New F32 targets, new executor results and new profile naming do not reinterpret those controls or their four-ratio API.

## 8. Readiness states and implementation packages

Readiness is a typed **per-case** record, not a single supported-shape boolean. Proposed `CaseReadiness` preserves independent input, implementation, layout/level, resource, target and execution gates: `MissingInput{binding}`, `InputConflict{expected,actual}`, `MissingCode{capability}`, `LayoutUnproved{stage,reason}`, `LevelInadmissible{trace}`, `ResourceSkipped{need,free}`, `TargetUnlocked`, `AwaitingUserDecision{scope}`, `Ready{plan_hash}` and terminal `Failed{phase,error}` / `Measured{receipt}`. Invalid registration combinations are errors, not missing experiments. Input failure stops before HE allocation even if some geometry can be planned. `Ready` means prepared and admitted, not measured or authorized for full encrypted blocks.

All21×seed combinations remain enumerable; released block seeds3–9 retain missing captured exports. Full encrypted eMLP2/3 execution retains the user hold regardless of code or subset-test success. ## 11. D6b concrete rationale and API (bounded implementation)

`study_plain::PlainState::<f32/f64>::new(&MaterializedProfile)` borrows exactly one immutable materialization and selects its corresponding `NumericInputs` through a sealed scalar trait. It clones only the initial model into private mutable parameter arrays, initializes unscaled velocity to zero, and converts momentum once to the chosen scalar. `step_plain(&mut state)` takes no rows, mutable metadata, rate or update index: it consumes the bound profile's next exact planned row slice and once-cast rate, then advances its update/sample counters only on success. `evaluate_plain(&state)` evaluates the bound held-out data; `predict_plain(&state, &[T])` predicts one supplied feature row without changing training inputs. Parameters, unscaled velocity, dtype/cast policy, input identity and progress have read-only views. There is no public fixture constructor or full-training runner.

Arithmetic order is explicit scalar Rust operations in T, with no explicit FMA, BLAS or parallel reduction. Dense forward loops traverse samples, output channels, then ascending input channels, accumulating products from zero and adding bias last. Activation is `z*z`, `(z*z)+z` or identity. Each stage's output delta is `(prediction-target)*rate.delta`, then activation derivative; hidden deltas sum ascending output channels before their derivative. Gradients traverse samples in consumed order, then output and input channels; sums divide by the actual valid sample count in T after the complete sum. All logical padded output channels contribute; labels generate one at the real class and zero elsewhere. Every stage forward cache is captured before any parameter change, and no gradient crosses its declared input boundary.

Updates traverse canonical layers, row-major weights and then active biases. SGD subtracts `rate.mean*gmean`. NAG stores `Vnew=mu*Vold+gmean` and subtracts `rate.mean*(gmean+mu*Vnew)`; it does not use the kernel coefficient or full-plan reference as an optimizer rate and never rescales velocity at a schedule change. Disabled bias arrays and their velocities stay exact zero. Unsupported decay/optimizer/loss conventions fail construction. Counts cast directly to T for arithmetic and invalid/nonfinite intermediates fail without clipping. All staged gradients precede mutation; no general rollback is promised if an update fails mid-mutation. Any failed numerical step poisons the state permanently; success counters remain unchanged and subsequent step/prediction/evaluation fail. Read-only arrays remain available for failure inspection. Exhaustion is a distinct non-poisoning error.

Prediction follows declared stage representation layers and the final output stack, ignoring local heads. Evaluation rejects nonfinite logits including padded channels and restricts argmax to real classes. D1's `total_cmp`/last-maximum tie convention is retained, including signed-zero ordering; integer correct/test counts precede the optional F64 ratio. No loss scalar is reported by this bounded API. Compiler/executable provenance, full reference artifacts, target locking, campaign execution and performance evidence remain later gates.
