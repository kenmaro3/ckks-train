# Study profile input contract

Status: implemented, locally validated and independently reviewed after the source-cardinality fix. Training execution and numerical materialization remain separate gates.

The profile resolver prepares host-side inputs for the 21 profiles registered at D0 commit `8eabcdd4cd46b3144c5a222ddb0ce533ee627b49`. Resolution and preflight allocate no HE objects, train no model, and authorize no execution.

Captured source JSONs contain initialized-array digests but no independent order-file digests. Root therefore approved a separate `configs/experiment_input_locks.json` integrity lock, generated mechanically from the exact tracked Git blob bytes at that reviewed D0 commit. It covers the two captured config JSONs and their sixteen existing per-model/per-seed orders. The generator checks current working files against those historical blobs before writing the lock. This is a lock of the reviewed repository snapshot, not new measurements or upstream attestation. Hashing current order bytes during preflight would accept a changed order as its own expected value; that alternative is rejected. Preflight uses the portable committed lock without Git and never repairs, refreshes, fetches or exports missing inputs. A missing lock entry is a missing input; a digest mismatch is corruption/conflict. Raw captured JSONs stay unchanged. Both registry and lock identities are explicit source constants; rebuilding against a rewritten lock does not make its new digest trusted. Updating either pin requires an independently reviewed source change. The stdlib generator tests compare deterministic output bytes with actual historical Git blobs and reject altered working config/order bytes and missing Git objects using read-only Git access; no fetch or workspace raw-input write occurs.

`StudyRegistry::load(root)` accepts the exact reviewed registry SHA256 and the explicit reviewed integrity-lock SHA256 (`APPROVED_INPUT_LOCK_SHA256`). `resolve(profile_id, seed)` requires an explicit registered ID and seed0–9. It binds registry dataset/model references, source config/value digests, real/padded classes, named layers and independent local-head roles, activations, bias, loss, optimizer, rate units, fixed split, initialization, order coverage and selected-seed schedule pointer. Conflicting source graph/shape/bias/activation/stage barriers fail closed. The faithful eMLP1 reference is the original784-input (28×28) subset source, with original MNIST10 classes padded to16; those source endpoints are independently validated and are not equated to the selected adaptation's4/30/196 inputs or Iris/WDBC output widths. There is no upstream-default lookup or external baseline adapter. Missing eMLP2/3 exports for seeds3–9 resolve metadata with `MissingCaptured`, required order path and absent digest; preflight returns typed `MissingInput`, never seed0 values.

Three readiness boundaries are explicit:

- `metadata()` and `data_request()` declare bindings; they do not verify dataset bytes or materialize local initialized arrays.
- `preflight(None)` verifies source/config locks, captured arrays/order/schedule and the update/checkpoint plan. Its `PreparedInputs` does **not** establish dataset readiness. An optional additional caller order lock must match the registered selected path and digest; it cannot replace the portable lock. Captured matrices are checked as `in × out`, then explicitly transposed to logical `out × in` on return. Layer names, physical/logical shapes and orientation remain in metadata.
- `prepare_dataset()` returns `PreparedDataset` only after captured/source preflight, every required dataset-file digest, the canonical D1 `load_dataset` request and its class/shape/split/preprocessing checks succeed. This combined method is the future adapter's host-side gate before HE parameter/key/evaluator allocation. It performs no model initialization, training, HE admission, metric collection or launch.

Iris binds the bundled CSV and existing seed2020 partition,120/30 rows, training-only z-score,4 features and3 real classes. WDBC binds the existing UCI SHA256, fixed stratified split seed0,455/114 rows, training-only column min-max,30 features and2 classes. Captured MNIST binds196 features,4800/10000 arrays unchanged: manifest files/pipeline/row_order/scaling must agree with the pinned captured eMLP1 source JSON; array-file hashes come from that source. Fashion binds the four existing unpacked IDX SHA256 values from the repository fetch script as read-only metadata,60000/10000 published split, existing14×14 resize/training-only min-max and10 classes. The script is never executed. Dataset preparation returns D1 source hashes and actual split indices; missing/corrupt data cannot be promoted to prepared inputs.

Local initialization stays a deterministic `GenerationRecipe`. For new profiles, ChaCha20 uses the existing bench key construction `[role, seed, seed, ...]`: keys1, initialization2, shuffle3, encryption4, refresh5, with persistent independent streams. Exact Iris preserves its existing master key (little-endian study seed u64 in bytes0–7, remaining bytes zero), first `Rng::fork` for initialization and second for shuffle; no legacy control is reseeded. The source sampler derives each fork from four successive little-endian `next_u64` words.

The recipe orders layers as the metadata graph: block forward then its head, in ascending block order, followed by the two output-stack layers. Weights draw logical `out × in` row-major. Normal initialization uses sigma0.2 and the existing Iris Box–Muller cosine draw: `u=(next_u64 >> 11)*2^-53`, `u1=max(u,1e-300)`, `sqrt(-2 ln u1)*cos(2πu2)`; weights then enabled biases for each layer. Xavier uses `sqrt(1/(fan_in+fan_out))` times `2*u-1`; each layer's output-width bias draws are consumed then discarded when bias is disabled, matching `twin::init_net`. No generated values are returned or claimed by resolution/preflight.

New local-order profiles apply the persistent shuffle stream to a fresh canonical `0..train_count` permutation each epoch using descending Fisher–Yates and `Rng::below` (unbiased rejection sampling). Exact Iris preserves in-place shuffling of the preceding epoch's fixed-split source-index vector; equivalently adapters may carry its permutation of canonical D1 training rows. Fixed train/test membership never depends on study seed. Complete epochs declare `FullPermutation`; WDBC drop-last declares `UniqueSubset{samples_per_pass:448}` from the full455-row epoch permutation and drops7 rows each epoch. Local initializer generation and FP32 arithmetic remain D2c/D6 duties.

Released captured orders already contain ten4800-row passes in one flat48000-index stream. The shared parser preserves the existing captured text semantics: full comment lines are ignored, only the last TSV field contains indices, and that field accepts whitespace/comma tokens. It verifies the entire file hash before parsing, then exact pass count/cardinality, index range and uniqueness. Captured files are never repeated ten times. Locally initialized MNIST2020 borrows only the explicitly registered eMLP1 order/schedule; the new D1 `preflight_order_schedule` validates those inputs without requiring irrelevant donor weights.

B48/B64/B128 consume1000/750/375 actual updates. For every captured update, the exact source schedule index is `floor(cumulative_processed_start / source_batch48)`. No truncation, epoch reset or coefficient interpolation occurs. RSS mean-gradient rates multiply the source coefficient by actual valid logical batch size; adapted2020 multiplies by its registered fixed nominal logical batch and retains the separate `2/classes` delta multiplier. Exact Iris mean-MSE rate remains0.1. Padded eMLP outputs participate in RSS/deltas with zero targets; accuracy uses real classes only.

Checkpoints occur at the first actual update endpoint at/after each logical boundary. B128 endpoints are updates38,75,113,150,188,225,263,300,338,375 and processed samples4864,9600,14464,19200,24064,28800,33664,38400,43264,48000. The returned plan records actual valid counts, source indices/rates, crossed boundary IDs and exact-boundary flags. Disjoint intervals alternate38/37 updates and4864/4736 samples, conserving375 updates/48000 samples. The plan supplies no observed accuracy/time or invented exact-epoch counters. D6 must attach cumulative metrics at these actual endpoints; D8 must subtract consecutive cumulative records and use actual interval denominators.

This module does not establish planner/security/capacity admission, actual FP32 reference/target locks, encrypted or external execution, or physical performance. D2c must implement recipe materialization and numerical adapters using these exact bindings. D6 must provide binary-owned source/build/input provenance and actual endpoint metrics. Existing FULL command paths/results/seeds/gates are untouched; new profile resolution does not grant launch authorization.
