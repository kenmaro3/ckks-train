Implementation: reviewed structural receipt package, including F1/F2 corrections, 2026-11-06. Native Mac focused validation passed; Linux production metadata, encoding feasibility and internal EvalMod feasibility remain unvalidated or unsupported as specified below.

## Recommendation and contract

Implement one small CKKS-owned package that derives exact *structural* bootstrap metadata
from actual `CkksParams` and `BootParams`, without constructing `DiagMatrix`, slot vectors,
`Encoder`, evaluator, ciphertexts, RNG or keys. It must distinguish four objects:

1. Stored DFT offset support, which determines the BSGS shape.
2. Main and second term support, which determines sparse encoding's `Some` positions.
3. The full shape-based rotation-key union actually generated by `BootstrapKeys`.
4. Executed rotations, with per-term multiplicities, which determine operation counts.

These are not interchangeable. `DiagMatrix::mul` retains a sum-offset key even when all
its entries are zero. `conj_sandwich` retains keys when it zeroes an entire parity.
`encode_complex_sparse` tests the pre-rotated **unencoded** complex vector for exact zero;
it does not prune an encoded plaintext that rounded to zero. Therefore exact Some support
does not require encoding or a prediction of quantization, provided the special DFT
support/non-underflow argument below is established. An encoding failure still prevents a
bootstrapper from being constructed: cost is the exact successful-execution cost, not a
promise that construction or execution will succeed.

The small EvalMod coefficient vector is a separate necessary exception to coefficient-free
structural computation. Reuse `evalmod_coeffs` and the existing recursive cost simulation:
its branches depend on actual F64 zero tests and `split_coeffs` subtraction. Do not replace
that computation by an ideal odd polynomial or a degree-only formula. This allocates
O(degree) scalar coefficients, never DFT matrix coefficients or encoded vectors. If root
requires **no polynomial coefficients either**, exact general EvalMod cost remains
`MissingCode`; parity and degree alone cannot discharge it.

## Public receipt and identity

Proposed `bootstrap::metadata::BootstrapMetadata::new(&CkksParams, &BootParams)` returns a
private, immutable receipt with borrowed read-only slices or copied scalar accessors:

```text
schema_version, parameter_identity_bytes, descriptor_identity_bytes
declared_main_secret, declared_ephemeral_secret
input: CtMeta(level=0, scale=Delta), output: CtMeta(level=after, scale=Delta)
ctos_stages, stoc_stages: [DftStageMetadata]
evalmod: { declared_degree, effective_coefficient_support, depth,
           input, polynomial_target, double_angle_targets, output, cost }
generated_keys: { rotation_steps, conjugation, relin, sse_to_sparse, sse_to_main }
execution_rotation_steps, per_direction_cost, cost_per_boot
proof_scope: StructuralCostAndBoundaryScales
```

Each DFT stage stores direction, original low/high butterfly bit indices, apply-order
ordinal, stored-offset representation, `(d,stride,offset,baby,giant)`, main/second kept
window indices, per-term baby steps, shared giant steps, input/output CtMeta, exact product
label bits, diagonal-scale bits and folded-factor bits. `second=None` differs from an
empty term. No writable public fields, deserialization into unchecked receipts, mutable
BootParams reference, or API returning an admitted runtime session.

Identity is content identity, not Arc identity. Encode versioned, domain-separated bytes:
fixed ASCII domain and u32 schema/algorithm revisions; u64 little-endian lengths and
integers; explicit u8 enum/Option tags; actual ordered q and p values, q_bits and p_bits
(the latter are used by `scale_at`), log_n, Delta.to_bits(), dnum, declared main weight;
every BootParams field including the two optional weights. Derived descriptor bytes also
encode ordered stage receipts, normalized keys, all seven counters and actual EvalMod
coefficient bits (or their independently versioned digest). Preserve F64 bits, including
signed zero. Never hash Debug text, preset names or only prime bit widths. Retain canonical
bytes for equality; a SHA-256 digest is an optional transport label using an existing
approved dependency, not a reason to add a cryptographic dependency here. Platform-varying
transcendental results can change the descriptor identity despite identical input identity.

`None` main weight means the *declared key-generator contract* of dense ternary sampling,
not an attestation of a sampled secret or its realized Hamming weight. Parameters contain
no actual secret. `Some(h)` declares fixed weight h. Validate h in 1..=N because the builder
can set an invalid value. Keep the ephemeral declaration separate. A runtime binder must
check parameter contents/Arc rules and actual key bundle manifests; metadata cannot prove
keys exist, establish their provenance, or certify their cryptographic security.

## Checked constructor and resource bounds

Before calling legacy `BootParams::validate`, any shift, `next_power_of_two`, multiplication
or allocation, validate log_slots, full packing, nonzero bands/K/degree and weights; compute
checked band sum, `degree+1`, its checked next power of two, depth plus double angles,
and every index/size conversion. Require existing DFT domain log_slots in 1..=16 and each
DFT band in 1..=log_slots (BootParams validation alone does not enforce this). Require
double_angle < 64 before the existing `1u64 << r`. Require bands leave at least one compute
level. Then call the existing semantic validation, including minimum K and secret agreement.
Reject unsupported values with contextual `InvalidParams`; no panic or wrapped size.

Do not alter the legacy validator's behavior implicitly. A private preflight used by this
new constructor is sufficient; reuse it in runtime only if separately accepted as a narrow
hardening change. The source's unchecked `levels_after_boot` sum is not safe to call first.

DFT structure can be represented by O(levels) interval descriptors and iterated in O(slots)
space or less: no slots-by-diagonals arrays. At log_slots<=16, checked compact bitsets for
all per-stage supports and the normalized key union have an explicit O(levels*slots) bit
upper bound; one temporary support bitset can be reused. Prefer arithmetic support
predicates and compact key vectors so the default allocation is smaller. Publish calculated
metadata allocation/work bounds, not an allocator RSS claim. Runtime key/table memory is
outside these bounds.

EvalMod interpolation is O((degree+1)^2) work and O(degree) peak coefficient storage; count
recursion must also have a checked work/space bound. Provide `new_with_limits` with explicit
metadata-only coefficient/work budgets; `new` uses a documented default (proposed maximum
4096 coefficients and 2^24 interpolation terms). Check the estimate before allocation and
use fallible reserves. Exceeding that operational budget is `MetadataBudgetExceeded`
(initially a contextual InvalidParams if no core error addition is approved), not evidence
of mathematical invalidity or a substituted approximate count. An explicitly larger budget
can describe the same supported parameters. All registered default_n16 cases fit by design;
their actual construction remains a required test. Do not shrink a registered preset or
call a dense-DFT fallback lightweight.

## Exact DFT supports and BSGS derivation

Let n=2^log_slots be the slot count. A forward group contains distinct contiguous butterfly
distance bits a..b, with stride s=2^a and r=b-a+1. `stage_radices` splits log_slots evenly,
placing extra bits farthest from distance1; retain that existing function. Forward applies
the groups low to high, inverse reverses groups and reverses multiplication within each.
Start with stored offsets {0}; for each distance h union the offsets plus {0,h,n-h}
modulo n, exactly matching `DiagMatrix::mul`'s insertion rule. This recurrence requires no
coefficient generation and is a useful independent test oracle.

For these contiguous groups only, the equivalent compact stored support is

```text
S(a,r) = { (s*t) mod n : -(2^r-1) <= t <= 2^r-1 }.
```

Normalize and deduplicate, especially the highest group that wraps. This is stored support
first, not an assumption that arbitrary stored diagonals are nonzero. Its nonzero support
can be proved for this construction: within each block of 2^(b+1), lower a bits remain
fixed and the r selected bits of row and column vary independently. For any fixed row and
column with those fixed lower bits, the butterfly network has exactly one nonzero path:
each selected bit is touched once. Any integer difference t in the stated interval has a
pair of r-bit numbers with that difference. Thus every stored offset has a nonzero-entry
witness. Reverse traversal/inverse butterflies preserve unique connectivity. There is no
sum of two nonzero path amplitudes to cancel; other multiplication summands are exact zero.
The same argument covers every valid grouping, including one group, r=1, and n=2.

The proof must also cover the actual finite F64 implementation, not ideal roots of unity.
At most16 factors occur; forward roots have magnitude near1, inverse factors near1/2.
For the supported numerical environment, establish explicit conservative bounds, e.g.
each generated root magnitude in [1/2,2], complex products retaining positive norm with
ordinary F64 error bounded well below that norm, and no overflow/underflow across16
products. Folded bootstrap factors are positive real: 1/K with integer K<=usize::MAX,
or 1/(2*pi); their l-th roots, the inverse half factors and the CtS extra1/2 remain far
from subnormal range on the stated 64-bit K domain (a loose lower bound 2^-128 suffices).
Multiplication by i, conjugation and zeroing parity do not invalidate the witness.
The initial exact-support claim is limited to explicitly verified 64-bit target/toolchain
environments using the existing root and complex-arithmetic implementation. The finite
root-domain checks, complex division/product bounds, and folded-factor checks must cover
each claimed environment. The current usize modular-power routine is not generally
32-bit-safe over log_slots <= 16; 32-bit runtime support is not claimed by P1b and remains
outside this package. An unverified environment retains MissingCode(DftKeptSupportProof).
Rust transcendental precision is not universally specified. The production constructor
does not generate these roots.
If this premise cannot be established, return a specific
`MissingCode(DftKeptSupportProof)`; do not label ideal support exact or allocate DFT vectors.

Factor rho keeps support. CtS's last, distance1-containing group has main kept offsets
`o in S where o is even`, and second kept offsets `o in S where o is odd`.
The stored keys of both are still S. All other CtS groups have one term with support S.
StC's first group has two terms, both with support S; all later groups have one.
This parity rule is about normalized slot offsets (n is even). Prerotation permutes a
vector and cannot change all-zero status. Some presence is therefore exact independently
of plaintext rounding, conditional on successful encoding.

Extract `shape_from_offsets(n, offsets)` once from `DiagMatrix::shape`; runtime calls it
with stored keys and metadata calls it with S. Preserve signed representatives
(-m/2,m/2], next-power-of-two coverage, aligned negative offset and full-wrap fallback.
Reuse `bsgs_split` and `bsgs_rotation_steps_with_offset`; validate their panic preconditions
first. Window index i corresponds to `((offset+i)*stride) mod n`. Membership in the above
main/second supports determines kept[i]; never recompute shape after pruning parity.

Generated rotation requirements are the normalized, zero-removed sorted union of the
**full** BSGS window baby/giant steps for both directions. Execution sets and counts use
kept membership. Record rotation requirements modulo n in 1..n, conjugation separately,
and distinguish an operation occurrence from a unique key. Identical steps used in two
terms need one key but can incur two rotations. Do not substitute
`LinearTransform::rotation_steps` (also full shape) for execution-needed rotations.

## Counts and stage scales

Extract a private checked `sparse_transform_cost(shape, kept_terms, direction, split)`
kernel. Runtime `transforms_cost` supplies `entries().is_some()` and metadata supplies
its support predicates. For baby B and giant G:

* ct_pt_mults is the sum of kept entries across terms.
* For each term, charge each nontrivial j*stride, 1<=j<B, once iff any kept[k*B+j].
* Charge each nontrivial (offset+B*k)*stride once iff any term has a kept entry in block k.
* Charge one rotation for CtS's split conjugation and one for CtS's final conjugation.
* Charge one rescale per stage; other fields are zero.

All nontrivial checks use modulo n. Store per-term execution steps as well as normalized
union so multiplicity is inspectable. Preserve the public runtime counter signature if
possible: the existing encoded shape has bounded counts; its wrapper may use the checked
kernel with a documented invariant. New descriptor arithmetic uses checked u64 addition,
multiplication and conversion for every one of seven fields and the total key switches.
No unchecked `OpCounter +=` in the public fallible descriptor path.

For EvalMod, evaluate the existing bounded `evalmod_coeffs` once. At r=0 even coefficients
are explicitly zeroed; r>0 uses the actual cosine path. Reuse `split_coeffs`, `optimal_split`
and the existing CostSim recursion with checked increments, retaining its rposition zero
test, leaf nonzero tests, power cache and lazy component-count relinearizations. This is
where cancellation can occur; the DFT unique-path proof does not apply. Do not trim declared
degree for depth: `chebyshev_depth` uses original vector length even if trailing coefficients
are zero. Add r ct_ct_tensor, r relins, r rescales. Bootstrap total is
CtS + 2*EvalMod + StC, with sse_switches=2 iff ephemeral_hw is Some, bootstraps=1.
Return all fields: rotations, relins, ct_ct_tensor, ct_pt_mults, rescales, sse_switches,
bootstraps. A measured runtime counter already includes this work.

Extract pure stage specifications and geometric `scale_path` once from existing constructor
and linear code. Retain exact F64 operation order: q0=params.q()[0] as f64;
S=params.scale_at(top-ctos_levels); StC input is `S*params.scale()/q0` in that order;
CtS factor1/K, StC factor1/(2*PI). CtS starts at top and ends at top-ctos_levels.
EvalMod ends depth levels below that, retains S, then drops unused EvalMod band levels.
StC starts at after+stoc_levels and ends at after=top-checked_band_sum, exactly Delta.

For every DFT stage, call P1a `exact_product_scale_at` and `target_plain_scale_at` with
the exact source/target; store the searched label and diagonal-scale bits. Do not introduce
an evaluator solely for `diagonal_scales`. Runtime and new metadata consume the same pure
path; preserve legacy finite-domain behavior, explicitly retaining the P1a distinction that
pure metadata rejects nonfinite intermediates legacy code may permit.

Double-angle target planning can be extracted from `eval_mod` as a private pure helper:
backward from S, sigma=exact label at the actual level, then the existing nearest-first
0,+1,-1,...,+16,-16 ULP `reachable_near` search around sqrt(2*sigma), using P1a's exact
label helper. Store targets and validate the same square relabel tolerance. Do not confuse
this ±16 search with the ±8 exact-product search. A complete EvalMod internal scale proof
would additionally need Cheb::ensure/rec/leaf metadata and its distinct 2^126 rounded
constant bound; P1a scalar's 2^62 bound is not that helper. P1b must expose that as
`EvalModInternalScaleUnvalidated` until extracted and tested. Boundary targets and exact
cost conditional on successful runtime execution remain useful and correctly named.

Source-derived default expectations, not newly run evidence: StC shapes are
(16,1,-8), (32,8,-16), (32,128,-16), (16,2048,0); CtS reverses them. CtS totals
34 rotations/93 ct-pt; StC35/108; each has4 rescales. Existing default EvalMod source
records23 tensors/20 relins/24 rescales/71 ct-pt per component. Consequently the expected
seven-field bootstrap tuple in the field order above is (69,40,46,343,56,2,1), total111
key switches, output level16/Delta and32 rotation keys plus conjugation. These are
test literals for this exact default, never a global cost constant.

## Key roles and honest admission boundaries

Record a caller-provided relinearization key and the bootstrap-owned Galois bundle at full
ordered Q*P, with N,dnum,alpha and parameter identity. SSE adds two distinct roles:
main->ephemeral at q0*P, level0, one digit; ephemeral->main at full Q*P, top level, dnum
digits. State declarations and directions explicitly even for a sparse main key; the
legacy `to_dense` name does not prove the destination is dense. Conjugation is one Galois
key used twice. Distinguish required maximum basis from the lower levels at which a key
is used. Do not merge training and bootstrap key bundles into a claimed resident-memory
union: current runtime owns separately generated bundles.

A returned receipt establishes structural support, required key shapes, boundary labels
and successful-execution operation counts. It does **not** establish that all encoded DFT
coefficients fit Q/2, encoded values remain nonzero, EvalMod internal scalar operations
succeed, ciphertext slots satisfy |m|<=1, overflow integers stay in the approximation
interval, declared secret assumptions are realized, acceptable precision, a security
estimate, runtime key availability, host/GPU resource fit or measured performance.
Keep separate status fields/issues for encoding feasibility, EvalMod internal scales,
range contract, precision, key binding, security, memory and backend. Structural success
must not become `Ready`, `GraphLevelScaleAdmitted` for the entire bootstrap, or a claim
that missing code in a downstream planner is closed.

## Implementation package and independent gates

One focused package is recommended: new `bootstrap/metadata.rs`, narrow exports; private
linear support/shape/count/scale helpers; checked reuse of polynomial cost and double-angle
target helpers; a runtime metadata consistency consumer; new focused metadata tests.
Do not rewrite coefficient arithmetic or general HeOps, change key-generation semantics,
prune runtime keys, alter bootstrap presets, or fold NN planner implementation into P1b.
Extract helpers once and keep runtime adapters narrow. Preserve legacy behavior outside
the explicitly checked pure domain. Cost/shape logic shared with runtime prevents drift;
it is not the only oracle used for tests.

Future RED/GREEN obligations, with no tests run during this design:

1. Actual n16_boot/default_n16 constructs metadata without Encoder/evaluator/DFT vectors
   or HE/key generation; full seven-field literals, identity, stage shapes/output and
   source-derived key cardinality above. Verify the source call graph and bounded storage.
2. Independently enumerate small butterfly row/column connectivity and stored-offset
   Minkowski sums for every log_slots1..6, every legal grouping and both directions.
   Compare every stored and kept window bit, wrap cases and parity split. Separately
   compare actual small DFT zero vectors (not only another caller of the new helper).
3. Small encoded fixtures compare Some/None presence, plaintext scale bits, stage target
   bits, full-shape keys and execution-needed sets. Include a deliberately tiny encoding
   that rounds a nonzero vector to zero yet remains Some, if accepted by that encoder;
   do not assert this case without inspecting encoding limits.
4. Constructed small real Bootstrapper compares all cost fields, exact output, keys and
   stage metadata for SSE Some/None, r=0/r>0, odd/even declared degrees and unequal legal
   CtS/StC groupings. Use valid K for each main/ephemeral weight. Small arithmetic cost
   tests exercise trailing/intermediate coefficient zeros and split cancellation.
5. Malformed overflow/usize::MAX bands/degree, r>=64, DFT band>log_slots, partial slots,
   invalid weights, minimum scale/unreachable target, nonfinite intermediates and budget
   excess all return explicit errors before prohibited allocation. Changing ordered primes,
   dnum, scale bits, weights or any BootParams field changes binding identity.
6. Runtime observed bootstrap counter equality can reuse a bounded existing small fixture;
   secure key generation/full bootstrap is unnecessary. Preserve existing legacy tests and
   independently enumerated literals so a shared-helper bug cannot validate itself.

Root choices ratified after independent review: polynomial scalar coefficients are permitted within explicit
metadata budgets; structural cost success is conditional and does not imply encoding or
internal EvalMod scale admission; supported-platform non-underflow premise receives a
specific proof/test gate; canonical identity bytes need no new hashing dependency.
If any proof remains unresolved, retain its named MissingCode/Unvalidated boundary and
specific follow-up, while keeping all registered default profiles in scope. No source
work starts merely because this design file exists.


## Ratified concrete API and process proof refinement (2026-11-06)

Root ratified the corrected API proposal (SHA-256
`8632764ee72887339e53f7d82c64ded086bee7e3e336f984642a47e80fc9dbd3`)
and released the bounded source package after D6c1a `6aba8f4`. The following refines the
no-token constructor sketched above; it does not expand the scientific proof scope.

`DftSupportProof::verify_current()` returns a private-field immutable process-local token
only after streaming the finite scalar root domain and checking the actual inverse
complex arithmetic. `BootstrapMetadata::new_with_verified_support(params,bp,&proof)`
and `with_limits_and_verified_support(params,bp,limits,&proof)` require that token.
Neither constructor generates DFT roots, matrices or vectors, or invokes Encoder, HE,
keys or RNG. There is no no-token constructor, process-global state, caller allow flag,
trusted serialized token or external attestation system. The token is reusable locally.

Narrow std-only CKKS build.rs embeds safely escaped Cargo-configured compiler `-vV` and
TARGET/HOST diagnostics, with explicit unavailable states. These identify the configured
compiler, not a complete build/source/executable attestation. Wrappers, arbitrary flags
and dynamic libm are not proved by diagnostic strings. Required unavailable diagnostics
and unsupported numerical environments return MissingCode(DftKeptSupportProof).
Target/compiler strings alone cannot prove runtime libm behavior: the separate actual
scalar checks, source-level ordinary binary64 error bound and per-descriptor folded
factor checks carry the conditional proof. The process must retain ordinary IEEE binary64
rounding/FP behavior and unchanged executable/library code after verification. No claim
of universally correct transcendental rounding is made. Exact validated environments
are recorded in the implementation report; this ratification itself is not a test result.

For group multiplication, unique connectivity leaves only one nonzero summand. The
ordinary complex product `(ac-bd,ad+bc)` has conservative normwise absolute rounding
error <=8u|z||w| plus a negligible subnormal allowance, u=2^-53. Actual streamed root
norms in [1/2,2] and inverse norms in [1/8,2] bound at most16 factors far from underflow.
Each actual descriptor checks the shared runtime folded magnitude/phase/extra-half
scalars, including actual powf outputs, rather than assuming monotonic or exact powf.
CtS conj_sandwich partitions parity and optionally conjugates retained odd-row entries;
retained magnitudes are unchanged, other entries exact zero. It never doubles them.
Small actual matrix tests and independent connectivity/offset enumeration remain required.

Public receipt structs have private fields with read-only getters. They expose full stage
shape/stored support/main-second kept windows, per-term execution multiplicities, required
full-shape key union/roles, actual EvalMod coefficient bits and declared-length depth,
exact scale/factor bits, all seven counters and checked key-switch total, immutable
configured-compiler/proof diagnostics, and resource bounds. The only proof scope is
StructuralCostAndBoundaryScales. EncodingQOverTwoFeasibility, EvalModInternalScaleUnvalidated,
encrypted range, approximation precision, actual secret contract, key binding, security,
runtime memory fit and backend support remain explicit unvalidated requirements.

CKKS-local BootstrapMetadataError distinguishes InvalidParams, ArithmeticOverflow,
NonFiniteIntermediate, MetadataBudgetExceeded, AllocationFailed, contextual ScalePlanning
(with original HekitError), and MissingCode(DftKeptSupportProof) with specific proof failure.
No core error change or generic runtime arithmetic hardening is authorized.

Default operational limits are4096 coefficients,2^24 interpolation summands,2^24 polynomial
work units and64MiB requested peak storage. All estimates/conversions are checked before
allocation. For c=degree+1,D=ceil(log2(c)), interpolation holds three c-scalar arrays;
recursive counting conservatively budgets c(D+1) scalar cells and a c-byte power cache,
with32c(D+1) work estimate and bounded runtime fuel. Persistent stages/support indices,
rotation lists, parameter/key snapshots, coefficient bits, temporary buffers and both
canonical byte strings are included in checked storage accounting. Every metadata heap
allocation, including proof-diagnostic copies, is fallible; static diagnostic strings may
be borrowed. No infallible clone/to_vec/collect can bypass that budget. These are requested
storage/work bounds, not allocator RSS, stack ABI or runtime key-memory estimates.

Version1 domain-separated typed canonical bytes bind ordered q/p and bit widths,log_n,
Delta bits,dnum,main weight and every BootParams field. Descriptor bytes additionally bind
ordered receipts, coefficient bits, keys/roles, all counters, scopes/issues and proof
identity. Preserve signed-zero bits; no new hash dependency. Different sufficient limits
do not change structural identity. No generic runtime complex-factor positivity restriction
is introduced by shared scalar helpers; positivity checks belong to bootstrap metadata.

### Implemented finite-support inequality and validation scope

The verifier's computed squared-norm gates are deliberately tighter than the proof's
norm bounds: root squared norm in[1/2,2], inverse squared norm in[1/32,2]. Ordinary
binary64 rounding of two products and a positive sum leaves ample slack for actual
mathematical norms in[1/2,2] and[1/8,2], respectively. This avoids treating a rounded
squared-norm endpoint as an exact real-norm bound. Actual observed extrema are retained
in the token. A separate finite residual probe uses the same complex multiplication.

For a component `fl(ac-bd)`, ordinary rounding bounds its absolute error by at most
`(2u+u^2)(|ac|+|bd|)` plus a subnormal absolute allowance; cancellation does not justify
a relative component bound. Combining real and imaginary component bounds and
`||( |ac|+|bd|, |ad|+|bc| )|| <= sqrt(2)|z||w|` gives the conservative8u normwise
bound. Sixteen factors with norm at least1/8 keep the product above2^-49, including
rounding margins; upper magnitudes remain below2^17. At most one summand per reachable
entry is nonzero; additions of the remaining exact-zero summands do not erase it.
Per-descriptor folded scalar magnitude is checked at least2^-66; the resulting witness
remains above the deliberately looser2^-120 bound. Conjugation, multiplication by i
and parity partition preserve the retained witness. Individual Cartesian components may
underflow/cancel to zero; the complex witness norm does not. No exhaustive HE-size DFT,
universal libm accuracy, coefficient-encoding feasibility or precision claim follows.

The current source gate permits only aarch64-apple-darwin with64-bit usize and available
configured-compiler/target/host diagnostics, plus mandatory current-process scalar checks.
The implementation report names the actual tested compiler/profile. This is a limited
numerical proof domain, not a general compiler attestation or a guarantee against external
FP-state/library mutation. Other targets return the named missing-proof boundary.


### Implementation review correction F1/F2

Linux production metadata is unsupported: verify_current returns the named
MissingCode(DftKeptSupportProof) boundary on unsupported targets (UnsupportedPointerWidth
on non64-bit targets, UnsupportedTargetEnvironment on identified unsupported64-bit targets).
Positive token/receipt tests are explicitly gated to the supported Apple64-bit target;
a public-verifier rejection test covers unsupported targets. Generic error/counter/iterator,
identity and folded-scalar checks remain active where no supported token is required.
Passing Ubuntu CI with this selection is not Linux numerical support; that requires a
separate finite-support proof/validation gate. Native Mac verification and host-only
compilation of an unsupported test branch must not be reported as Linux execution.

The original validation report incorrectly stated no secure-size HE/key generation occurred.
Its unqualified EvalMod regression filter actually ran n16_boot_keys_eval_mod, which
constructs N=2^16 parameters and generates keys including an approximately0.3GB relin key.
The independent reviewer repeated that filter before identifying the scope violation.
Both were unintended executions outside the authorized validation scope. Original logs,
commands and counts are preserved in before-fix1 artifacts; the corrected implementation
and fix reports disclose them. Future focused EvalMod commands explicitly include
`--skip n16_boot_keys_eval_mod`. This is neither scientific benchmark evidence nor full
numerical bootstrap admission. No production proof target or arithmetic was widened.
