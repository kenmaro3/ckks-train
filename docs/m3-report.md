## 0. 判定(冒頭、暫定)

**RQ1(研究計画 §4.3.2)は暫定。全長の 196 入力行(見出し)が未計測なので、判定は 784 入力の subset 行(ReBoot の暗号化学習スクリプトと同じ 784 入力、1008 サンプル、1 epoch)に基づく。判断は本人に返す。**

- **B = 64(見出しの配置 WN、R-41-F2)**: 鍵切替の比は ReBoot B = 48 に対して (a) 0.233、(b) 0.414、(c) 0.404。3 通りとも ≤ 0.70 で、**鍵切替の基準は subset で合格**。同一 CPU(i9-13900KF、12 スレッド)の wall-clock は ReBoot 公式の **0.447 倍**(サンプルあたり)で、**wall-clock の基準も subset で合格**。AU でも (a) 0.268 / (b) 0.586 / (c) 0.466、wall-clock 0.609 で合格。
- **B = 32(WN、R-41-F1)**: (a) 0.435 は合格だが、(b) 0.779 と (c) 0.756 は**不合格**。wall-clock は 0.838 で合格。AU は (a) 0.513 だけ合格、(b) 1.149 / (c) 0.891 は不合格で、wall-clock は **1.187(不合格)**。
- **B = 48**: 2 の冪のレーンでは走らない(R-M3-4)。式の値は 784 で 27.52 KS / サンプル(AU)、(a) 0.358 / (b) 0.782 / (c) 0.621。wall-clock は未計測。
- **精度(±0.5 pt)**: R-M3-15 により、判定は ReBoot の公開コードの全長設定(196 入力、4800 サンプル × 10 epoch、ReBoot の双子 0.9065 ± 0.0027)と比べる。その暗号化行は pending (R-41-FULL-1 / R-41-FULL-2)。subset では B = 32 が ReBoot より +0.71 pt、B = 64 が **−1.48 pt** で、平文の双子でもほぼ同じ差(+0.71 / −1.47 pt)が出る(B の違いによる学習の差で、暗号化の誤差ではない)。
- **その他の条件**: N は全行 2^16 で同一。セキュリティの条件は揃っていない。R-REB-4 の実パラメータを hekit と同じモデルで推定すると、ReBoot は 128 bit 未満: MITM なしのハイブリッドで BDGL16 127.8 / MATZOV 126.2 bit、MITM ハイブリッドで 121.8 / 121.5 bit(演算量のみ、メモリ約 2^104〜2^110)。原因は構成(SPARSE_TERNARY h = 192 と HEStd_128_classic、OpenFHE の表による検査は疎な秘密鍵を考慮しない)で、著者の主張の問題ではない(§3.3a、`docs/security.md`)。
- **まとめ**: subset では、**B = 64 は鍵切替(3 通りすべて)と wall-clock を満たす**。B = 32 は ReBoot のブートストラップ回数(502)を ReBoot 側にだけ数える (a) でしか満たさない。§4.3.2 の合格には、全長 196 入力行での鍵切替と、全長設定での精度 ±0.5 pt が残る。Plan B の発動条件は、いまの実測では成立していない(M2 での本人の選択 A を継続。§9)。

## 5. M0 の前提 1〜3 は実測でどうなったか

1. **compact W/V 再配置が CKKS で動くこと**: 動いた。Task 40 で n16_boot の (32, 1024)、B = 32 で `boot_count` 1、pack 31 回転 / unpack 191 回転(コストモデルと一致)、往復誤差 2^-22.8。学習でも 1 回のブートストラップ事象は W・U の 2 コンテナで 4 ブートストラップで、モデルの 4 と同じ(再配置なしなら 2·(32 + 16) = 96)。
2. **BOOT_KS ≈ 502**: hekit のブートストラップは**実測 111 KS**(回転 69(共役 2 を含む)+ relin 40 + SSE 2)で、精度 17.46 bit。502 は ReBoot(OpenFHE Meta-BTS、2 反復)のモデル値のままで、OpenFHE の回数は実測できない(記録しない)。ReBoot 公式の 1 回のブートストラップ時間は hekit の約 2.1 倍(31.0 s 対 14.6〜14.7 s、同一 CPU、12 スレッド)。
3. **B ≥ 64 で ReBoot(B = 48)と同精度が出ること**: 暗号化による劣化は小さい。B = 64 の双子との重みの最大差は 2^-14.07(AU)/ 2^-14.72(WN)/ 2^-14.65(F2)、test 精度の差は 0〜0.0001。ただし B を 48 から 64 にすると平文でも subset の精度が下がる(双子 0.7359 対 0.7506、−1.47 pt)。全長設定での B = 64 の精度は pending (R-41-FULL-1)。

- 公開コードの全長設定(0.9065)は論文の値より約 4 pt 低い。そこで R-REB-3 で、論文の記載(Table 8 / Table 2)どおりの設定を ReBoot の公開コードの平文経路で走らせた: 60000 サンプル、14×14、lr 0.001、weight decay 0.001、B = 48、50 epoch、シード 0〜9、lr は一定と ReBoot のスケジューラの 2 通り(`results/quadruped/raw/reboot_emlp1_paper_setting/summary.json`)。

|---|---|---|---|---|
| 一定 0.001 | 0.9535 ± 0.0010 | 0.9494 ± 0.0020 | 0.9513 ± 0.0012 | 0.9515 ± 0.0019 |
| ReBoot のスケジューラ | 0.9546 ± 0.0009 | 0.9495 ± 0.0023 | 0.9516 ± 0.0008 | 0.9525 ± 0.0008 |

## 8. 裁定と逸脱の一覧

### 8.1 M3 の裁定 R-M3-1〜15(全文)

- **R-M3-1**(n16_boot のバンド): 密な三値の EvalMod(K ≈ 25、Chebyshev + r 回の倍角)が 16 bit 以上で 8 レベルに収まらなければ、実装者はバンドの大きさを組み替えてよい。条件は levels_after_boot ≥ 12、精度 ≥ 16 bit、log PQ は Task 39 で再推定。Task 35 のテストの数値は文書に合わせて更新する。ゲート(精度、128 bit)は緩めない。誤りのコスト: 後でプリセットを変えること。
- **R-M3-2**: `test_tiny` は文書に「安全でない、テスト専用」と書く。ほかにセキュリティを迂回するフラグは置かない。
- **R-M3-3**: `BootstrapRefresher::bind_layout` は、サーバ側でブロック平均をしない限り、複製レイアウトに対して InvalidParams を返す。Task 41 の compact_pack(対角ごとに 1 レーン)→ ブートストラップ → compact_unpack(再複製)の経路は、作り方からブロックを置き直す。このことを Task 40 / 41 の文書に書き、1 ステップ後のブロック周期性をテストする。
- **R-M3-4**(B = 48): 2 の冪のレーンでは B = 48 は不可能。B = 32 は 1 暗号文、B = 64 は 32 レーンのマイクロバッチ 2 つで、勾配を足してから 1 回の更新・ブートストラップにする(ブートストラップを 64 サンプルで償却する。M0 の前提)。B ∈ {32, 64} で報告し、逸脱を記す。誤りのコスト: RQ1 の表の行が計画と違うこと。計画担当の追記: Task 42 の表は B = 32 と B = 64(配置 2 種)で ReBoot の B = 48 を挟み、B = 48 の式の値を併記する。B = 48 を走らせなかったことと理由を本人向けに書く。
- **R-M3-5**(SSE): 疎な秘密鍵へのカプセル化(Bossuat–Troncoso-Pastoriza–Hubaux、ACNS 2022)を採用し、レベル 0 で h' = 32 の一時鍵に切り替える(鍵切替鍵は mod q0·P)。q0 = 54 bit(q0/Δ = 2^12、入力のスケールは 2^42 のままなので Task 38 の ScaleMismatch の契約は変わらない)、特殊素数 P = 4 × 60(58 bit の桁での Q_d/P ≈ 1 の鍵切替ノイズを除く)。バンドは変えない(CtS 4 / EvalMod 8 / StC 3、levels_after_boot 16)。log PQ = 54 + 42·23 + 58·8 + 60·4 = 1724(≤ 1750)。予測 18.4 bit(ゲート 16、モデルは ±1〜2 bit。q0/Δ = 2^12 で補正なしの sine 誤差も 2^-21 に収まる)。BootParams に `ephemeral_hw: Option<usize>`(既定 Some(32))を加える。K = 13、次数 127、r = 1 はそのまま。理由: spec のゲート(≥ 16 bit、128 bit)は拘束的で、SSE は密な主鍵を保つ標準の方法。q0 = 52 は予測の余裕が大きいが、sine の余裕を arcsine 補正に回すことになる。誤りのコスト: Task 38 の実測が 16 bit 未満なら次は q0 = 52(2^10、予測 20.4)。
- **R-M3-6**(Task 39 の範囲): (a) 密な n16_boot を log PQ 1724 で(主ゲート)、(b) SSE 鍵(N = 2^16、h = 32)を log(q0·P) = 294 で、(c) h = 192 の主鍵を代替としてだけ(128 未満なら報告して使わない)推定する。Task 37 / 38 のブリーフ: mod-raise の前に SSE の鍵切替をする。BootstrapKeys が s → s' の鍵を持つ。KeyGenerator にハミング重み固定の疎な秘密鍵が要る。
- **R-M3-7**(R-M3-1 の下での組み替え): 大きい素数を CtS に、小さい素数を StC に置く(CtS は |値| ≈ K·q0 を扱うので、その平文符号化の精度がブートストラップを制限する。StC は m·Δ しか扱わない)。拘束条件の下で実装者が鎖を選ぶ: CtS の素数 ≥ 52 bit(レビューアの 56 が望ましい)、StC の素数 ≈ 36 bit、EvalMod のバンドと K・次数・r は必要に応じて、q0 54、P は全ての桁より 8 bit 以上大きい、素数の数は dnum で割り切れる、log PQ ≤ 1750、levels_after_boot ≥ 12(15〜16 が望ましい)、CtS の符号化の項を predict() と §6 に加えた予測精度 ≥ 16 bit。レビューアの案(計算 15、31 素数)は dnum 8 で割り切れないので数え直す。誤りのコスト: Task 36 の前にもう 1 回プリセットを直すこと。
- **R-M3-8**(EvalMod 7 レベル): EvalMod を r = 0、次数 127(同じ 17.4 bit、sine 誤差 2^-45.4)にすると、レベル最適の評価器(I2 で必須にした)で 7 レベルで済む。EvalMod のバンドを 7 × 58 にし、空いた素数を 16 番目の計算用素数(42)にする: q = [54, 42×16, 34×4, 58×7, 56×4](32 素数、dnum 8)、log PQ 1732、levels_after_boot 16(計画の値)。理由: 精度を変えずに計算レベル +1、log PQ −16 bit(安全性の余裕)。Task 37 はどのみちレベル最適の Chebyshev 評価を実装する。誤りのコスト: Task 37 が 7 レベルに収められなければ、r = 0・次数 127 の 8 レベル(e8dbe3e の鎖)に戻す。
- **R-M3-9**: SSE は Task 37 で mod-raise と一緒に実装する(ハミング重み固定の疎な秘密鍵 h' = 32、s → s' の鍵は mod q0·P、s' → s は mod Q·P、`mod_raise` の経路 = レベル 0 で s' に切り替え → 持ち上げ → 戻す)。Task 38 は組み立てるだけ。EvalMod の予算は 7 レベル(R-M3-8)、レベル最適の Chebyshev が必須。
- **R-M3-10**(Task 39 Step 1 と SSE): `n16_boot_sparse()` = n16_boot と同じ鎖で主鍵 h = 192、SSE h' = 32 はそのまま(mod-raise が見るのは h' なので K = 13 は有効)。Task 38 のブートストラップのテストは両方のプリセットで走らせる。推定は (a) 密な n16_boot を 1732 で、(b) SSE h' = 32 を 294 で、(c) h = 192 を 1732 で(代替。128 未満なら記録して論文には使わない)。計画担当の条件: (a) か (b) が BDGL16 か MATZOV で 128 未満なら、EvalMod の素数幅を 1 bit 削って推定し直す(レベルは落とさない)。
- **R-M3-11**(融合した更新経路、全文): Task 41 はコストモデルの融合した更新経路を実装する。
  - 勾配は reduce-only(複製しない)。
  - 最初の周期のレーン 0 のマスクが pack のマスクを兼ね、c = lr / n をそこに畳み込む。
  - compact 形へのレーンシフトはマスクなし(`compact.rs` に `compact_shift` を加える。費用は m − n_ct 回転、ct-pt 0、レベル 0、relin 0)。
  - optimizer(NAG の W / U)は、持続する compact 暗号文の上で計算する。
  - ブートストラップは compact の W / U にかけ、unpack するのは W だけ。
  - **バイアス**(Task 41 の実装): W2 のコンテナの空き位置(t = 16 と 32)に置く。ブートストラップも鍵も増えない。NAG の下でも素の SGD(速度のバイアス位置は 0 のまま)。次の順伝播の積のスケールで `compact_extract` によって取り出す。**忠実な設定(R-M3-12)では凍結する**(暗号化した 0 を置き、更新しない。畳み込む定数が 0 になるだけで、演算と回数は変わらない)。
  - 理由: ブリーフの字義どおりの経路は、モデルに対して +1 レベル / 反復、≈ +650 KS / 更新(+20 KS / サンプル、+54%)かかる。誤りのコスト: Task 41 が複雑になること。代替は字義どおりの経路で、そのときはそう報告する。
- **R-M3-12**(精度の忠実さ): `configs/reboot_emlp1_faithful.json` を加え、ReBoot の学習を再現する: lr_mean = 5e-4·B(ReBoot の和の勾配の歩幅)、momentum 0.9、バイアスなし(`--no-bias`)、Xavier 型の初期値(`--init xavier`)、出力 10(16 は ReBoot のパディング。注記)、subsample は ReBoot の添字がデータとして得られればそれ、なければ hekit のもの(注記)。まず Mac で平文の双子で確かめ(subset で ≈ 0.75 に届くこと)、それからサーバでの再走行を出す(WN の B = 32 と 64 が見出しの配置。AU は鍵切替が同じ)。旧設定は M0 の一覧に「忠実でない」と記録する。鍵切替の数は変わらない(バイアスを外すと +34 のバイアス項が消えるので両方を報告する)。実装では出力幅 16 を残した(パディングした行のデルタが隠れ層に届くので 10 とは等価でない。Task 41 の報告)。
- **R-M3-13**(入力の大きさ): 忠実な eMLP-1 は 196 入力(14×14、論文 Table 2 と全長設定のコードの経路)。hekit は d_in 196 を 256 にパディングして RQ1 の見出しと ±0.5 pt の確認に使う(当初の参照は論文 Table 4 の 94.61 ± 0.27、平文の ReBoot。のちに R-M3-15 で置き換え)。784 入力の走行(R-41-1〜4、F1 / F2)は補助の行として残す。両側とも ReBoot の `training_encrypted.py` の subset 走行と同じ 784 なので、F1 / F2 は置き換えない。M0 の忠実でない設定の一覧: `reboot_emlp1.json` の「784-32-10」→ 論文のモデルは 196-32-10(16 にパディング)。Task 41b: `--dataset-npy`、`--lr-schedule FILE`、d_in 196 → 256 での B = 32 / 64(+ 48 の式)の予測、全長のサーバ用コマンド。
- **R-M3-14**(全長設定の計画): ReBoot の全長設定 = 4800 サンプルで B = 48 を 1000 ステップ ≈ 10 epoch、lr は 5 epoch 一定の後にリスタート付きのコサイン。暗号化学習には hekit-nn の NiOptimizer にステップごとの lr(セッタと、NAG の速度の lr_new / lr_old による再スケール)が要る。Task 43 の後に実装する(Task 41c)。サーバの走行: RQ1 の見出しは WN B = 64(196)の全長 seed 0。精度の確認は B = 48 を 64 レーンで暗号化 seed 0(ReBoot のバッチ)と、ReBoot のシードごとの初期重みを使った hekit の双子を、ReBoot 自身の双子(シードごと)と論文の 94.61 ± 0.27 に比べる。ReBoot のコードがシード 0〜9 の初期重みと添字を出せるなら依頼する。196 での RQ1 の ReBoot 側は M0 のモデル(ラベル付き)。同じライブラリでの 196 の ReBoot レイアウトの走行は任意で後日。
- **R-M3-15**(精度の参照): ±0.5 pt は、ReBoot の公開コードの全長設定と同じ条件で判定する(シードごとに再計算した双子、平均 0.9065 ± 0.0027)。hekit の暗号化 seed 0 を ReBoot の双子 seed 0 と、hekit の双子のシード 0〜9 を ReBoot の双子のシード 0〜9 と比べる。論文の 94.61 ± 0.27(Table 4、平文、公開コードからは再現できない設定)は注記つきで併記する。判定の仕方を本人の決定事項に加える。

4. **バイアス**: 旧設定では素の SGD(R-M3-11)、忠実な設定では凍結。忠実な設定でもバイアスの演算(34 KS / 更新)は残る(§1.1)。

6. **784 の行は補助**(R-M3-13)。見出しの 196 全長行は pending。
7. **旧設定の 784 の走行(R-41-1〜5)は精度の比較には使えない**(R-M3-12)。KS と時間には使える。

9. **部分バッチの lr**: 1008 サンプルの走行の最後の更新は ReBoot の歩幅の B / n_valid 倍(§1.1)。
10. **provenance**: JSON の `git_commit` は走行時の HEAD で、ビルドしたコミットではない。Mac の NI の行は HEAD が 43f219f / f792aba、バイナリは 010a773 でビルドした(間のコミットは docs と results だけ)。サーバの R-41-1〜5 は 43f219f + 未コミットの 6 ファイル(hekit のライブラリのソースは含まない)、F1 / F2 は 3e0e99c のクリーンなクローン。
11. **研究計画の「32 スレッド」の値は取っていない**。同一 CPU の比較は両側 12 スレッド(§7)。
12. **AA の B = 64 は走らせていない**。
