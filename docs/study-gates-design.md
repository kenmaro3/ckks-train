## 6. Evidence custody and recovery

Carried M1's transaction design is now ratified: [exact proposal and independent review](../results/validation/task54-d7-gate-custody-design/README.md), proposal `fc938561`, SPEC/QUALITY PASS `31d9fb50`. Keep Full's existing `campaigns/<campaign>/profiles/p-<profile-slot>/cases/c-<case-id>/attempts/<attempt>` tree. Quick uses the disjoint `quick-campaigns/<campaign>/profiles/p-<profile-slot>/cases/q-<registration-case-id>/attempts/<operational-attempt>` tree and a narrow concrete adapter sharing the existing safe anchors/guard/publisher; Full Train existing-only opening is unchanged. The Quick stable case slot does not include attempt identity.

After actual gates and bounded records exist in memory, acquire the profile guard and validate eligibility before exclusively creating the named attempt. Publish fixed canonical-binary `inputs.evidence.bin`, `implementation.evidence.bin`, `layout.evidence.bin`, `resource.evidence.bin`, `user.evidence.bin` in that order, then Full admission or Quick preflight. Each evidence file is at most existing A=2,097,152bytes; its whole-file SHA256 is exactly the existing Gates evidence hash. Require durable no-clobber publication and exact retained FD/byte checks for all five before admission. Embedding evidence would change frozen admission bytes; publishing it afterward could leave an admission without durable evidence, so both alternatives are rejected.

Full retains unchanged admission/start paths and caps. Quick adds only `quick.preflight.json`, `quick.start.json`, `quick.end.json`, each within A, with distinct operational linkage. Hold the same store/attempt/evidence handles through start and checked begin; transfer immutable bytes and actual leases/accounting into the live frame before closing handles. No guard is held during training. A still-live origin-bound Quick caller may publish one linked operational end after actual return; recovery cannot fabricate it.

The exact proposal freezes recognized `.tmp-<closed-id>-0` through `-63` names and owner/mode/mount/cap checks. Safe recognized leftovers are preserved; unknown entries reject. A residual temp may share the final inode after uncertain cleanup, so ordinary finals do not gain the guard's special nlink1 requirement. Every named attempt blocks Initial, including empty or evidence-only attempts. Only a fully verified admission plus all five exact evidence files can become an explicitly selected Retry predecessor after resync; an orphan cannot. Recovery never promotes a temp, repairs missing files, resets eligibility or restores live authority. A before-link error is per-file and does not roll back earlier sidecars.

Quick is Initial-only in this bounded protocol. Repeating a case needs a separately recorded namespace within existing authority, preserving the original attempt; no automatic campaign rotation or extra generic approval is added. A first orphaned Full case may remain blocked in that campaign unless an older valid predecessor supports an explicitly authorized Retry. This conservative consequence preserves the frozen target protocol. The cost of an incorrect custody choice is stranded attempts or invalid durability evidence, so independent C01–C10 fault/identity/concurrency tests and later bounded native Linux checks remain required. This design supplies no successful durable run or scientific result.
