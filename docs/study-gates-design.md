## 2. Closed Full and Quick scope

Each of the same five concrete gate constructors accepts a private closed Full/Quick scope. Common facts retain exact execution/input/receipt/request/source/process/context ownership. Full requires actual verified reference/lock/threshold, Full consumption and the exact attempt/predecessor; its input gate compares the target reader's independently materialized selected receipt. Missing or placeholder target links cannot satisfy Full.

Quick binds full registration only as registration provenance, a separate operational identity, seed0/two-update consumed order and an operational attempt. It validates canonical source/materialization directly and has no target/reference/threshold fields or target-comparison claim. It cannot enter Full admission/start or be promoted into Full capabilities. All five substantive implementation/layout/resource/user checks remain; only the branch-specific target/lifecycle requirements differ.

New inner evidence records distinguish branches explicitly. Frozen full CaseIdentity, ExecutionBinding, Gates and admission/start bytes remain unchanged. Before source, freeze the eight named branch tests in the exact proposal, including missing Full target, target-free Quick, placeholder refusal, equal-hash cross-scope refusal and exact Quick consumption. This fixes the initial design contradiction without broadly optional target fields or a caller bypass flag.

## 3. Five actual capabilities and retained ownership

Inputs, implementation, layout, resource and user capabilities are privately constructed from actual checked facts/evidence, sealed to one scope, and consumed together. A hash, selector, parser or recovered receipt cannot construct them. Runtime-policy/outer binding comes from the actual retained runtime and closed CPU route. Original input/parameter/P1/plan/descriptor owners and the same accounting transfer into the genuine live frame before crypto; crypto dies before leases/accounting on every path.

Use a private process-wide checked, never-reused context-instance number plus ProcessStamp before admission. Admission compares the original instance, process and store/context pointer, obtains a fresh checked-input token borrowing the actual context for its independent lifetime, compares retained facts and carries the token into the live frame. It is not a serializable permit or dereferenceable stale pointer. This avoids imposing a context-lifetime-outlives-input-lifetime constraint or broad public lifetime changes. Overflow refuses; metadata-equal reloaded contexts differ.

Preserve the specified `begin_checked_he<'s, 'c: 's, 'p: 's>(StartedHeCase<'s,'c,'p>) -> Result<HeSession<'c,'p>, HeStartError>` boundary. Retain the same exclusive store borrow and attempt handles through start rechecks and accounted post-start `validate_plan_binding`, then transfer real owners/leases before keys. No candidate geometry rebuild, callback permit, recovery-to-live conversion or fake StartedHeCase is allowed.

## 4. Resource, authorization and durable evidence

PreparationAccounting covers requested application payload, not physical memory fit. A positive resource gate needs a complete applicable liveness model and actual usable host/cgroup/device capacity, distinguishing already-resident owners from incremental allocations. A held cooperative execution claim serializes participating runners but does not reserve RAM. Insufficient capacity before allocation is unmeasured resource skip; a later OOM is failure. Missing model terms remain missing evidence; no guessed headroom or threshold is added.

The user capability records the existing authorized task and exact scope; CLI cannot enlarge it. Retain the current full encrypted-block hold and actual scope/revocation checks without requesting another generic approval. Existing author/B/same-N questions do not stop ordinary authorized source work.

Carried Minor M1 is mandatory before protocol/gate source: freeze closed evidence paths/names/entries/caps, publication order, held-FD/guard/no-clobber/fsync ownership and all partial-state recovery/Initial/Retry semantics. No sidecar precedes guarded eligibility. Partial or orphan evidence never resets a named attempt; unknown entries reject. Admission evidence hashes must identify the exact retained durable bytes. New evidence encodings need independent vectors before encoder implementation.
